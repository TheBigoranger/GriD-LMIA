\chapter{\texorpdfstring{\codeplain{pdlmi}}{pdlmi}: Finite Certificate Assembly}\index{pdlmi@\texttt{pdlmi}}
\label{sec:pdlmi}

\code{pdlmi} stores finite certificates assembled from \code{pdvar} expressions or coefficient-backed \code{pdmat} inequalities. Square Hermitian inequality families use semidefinite constraints, other inequalities use entry-wise scalar constraints, and \code{pdvar} equality uses direct coefficient equations. Direct assembly is the default. The five explicit inequality alternatives are cell-wise P\'olya elevation, dense Putinar, tensor-window SparsePutinar, tensor-window SparseFullBox, and the dense full-box preordering. This class is the package boundary between Bernstein objects and ordinary YALMIP solver calls.

\section{Inspect Certificate State}
\index{PutinarOrder@\texttt{PutinarOrder}}\index{SparsePutinarOrder@\texttt{SparsePutinarOrder}}\index{CliqueSize@\texttt{CliqueSize}}\index{SparseFullBoxOrder@\texttt{SparseFullBoxOrder}}\index{BandWidth@\texttt{BandWidth}}\index{FullBoxOrder@\texttt{FullBoxOrder}}

All \code{pdlmi} properties have private set access and are readable with dot notation.  \code{Constraints} contains the assembled YALMIP entries. \code{Residual} and \code{Relation} retain the original comparison for rebuilding.  The remaining properties record the selected certificate state.

For example, \code{C.Relation}, \code{C.Residual.Degree}, and \code{C.UseSparsePutinar} inspect a wrapper. Selector methods return a rebuilt value, while assigning these properties is unsupported. Selected P\'olya and Gram parameters are stored as $1$-by-$\ell$ rows. An intermediate SparsePutinar result stores \code{UseSparsePutinar=true}, its order row, and its clique size. In one parameter, clique size one becomes actual Direct state. In several parameters, clique size one remains SparsePutinar. Any clique size greater than one that covers every active Gram basis becomes dense Putinar state. SparseFullBox separately uses \code{SparseFullBoxOrder} and the historically named \code{BandWidth} property to store its common tensor-window side length, with Direct and FullBox endpoints as described in \cref{sec:pdlmi-sparse-full-box}.

\label{sec:pdlmi-construction}

\arghead
\begin{itemize}[leftmargin=*]
  \item \code{expr} is a \code{pdvar} residual, or a coefficient-backed \code{pdmat} residual for \code{"<="} or \code{">="}. \code{relation} is exactly \code{"<="}, \code{">="}, or \code{"=="}. Inequalities are classified globally from the original coefficient family. \code{pdvar} equality is entry-wise direct coefficient assembly and accepts rectangular or nonsymmetric residuals. \code{pdmat} equality is instead the scalar logical comparison \code{A==B} and never creates a \code{pdlmi}.
  \item \code{UsePolya} is a logical scalar option with default \code{false}. Its bare form, \code{"UsePolya"}, and \code{UsePolya=true} with the degree omitted select increment one.
  \item \code{PolyaDegree=d} accepts one finite nonnegative integer scalar shorthand or an $\ell$-element vector and is stored as a $1$-by-$\ell$ row. It elevates the residual componentwise by $\vect{d}$ before assembling constraints. Supplying the degree by itself enables P\'olya and issues \codeerr{pdlmi}{ImplicitUsePolya}. \code{UsePolya=false} with any positive component raises \codeerr{pdlmi}{ConflictingPolyaOptions}.
  \item \code{UsePutinar} is a logical scalar option with default \code{false}. Its bare form and the explicit value \code{true} select the dimension-appropriate Putinar certificate at the smallest admissible order.
  \item \code{PutinarOrder=r} accepts one finite nonnegative integer scalar shorthand or an $\ell$-element vector and is stored as the $1$-by-$\ell$ absolute Bernstein Gram order $\vect{r}$, which is distinct from a degree increment. For one parameter, $\vect{M}=(M_1)$ and the default and minimum are $\vect{r}=(\lfloor M_1/2\rfloor)$. For two or more parameters, the default and componentwise minimum are $\lceil\vect{M}/2\rceil$. Supplying the order by itself enables Putinar assembly. Pairing \code{UsePutinar=false} with any explicit order, including zero, raises \codeerr{pdlmi}{ConflictingPutinarOptions}.
  \item \code{UseSparsePutinar} is a logical scalar option with default \code{false}. Its bare form and the explicit value \code{true} select SparsePutinar with default \code{CliqueSize=2}. Supplying \code{CliqueSize} or \code{SparsePutinarOrder} alone also enables this family. Explicit \code{UseSparsePutinar=false} conflicts with either parameter.
  \item \code{CliqueSize=b} is one finite positive integer tensor-window side length. \code{SparsePutinarOrder=r} accepts scalar shorthand or an $\ell$-element vector and is stored as the $1$-by-$\ell$ absolute Putinar Gram order $\vect{r}$. Its default and minimum are $(\lfloor M_1/2\rfloor)$ when $\vect{M}=(M_1)$ and componentwise $\lceil\vect{M}/2\rceil$ otherwise. Endpoint normalization occurs only after order validation. In one parameter, \code{b=1} returns actual Direct state. In several parameters, \code{b=1} retains SparsePutinar state. Any \code{b>1} satisfying $b\ge r_s+1$ for every direction returns actual dense Putinar state, while all other valid sizes retain SparsePutinar state.
  \item \code{UseSparseFullBox}\allowbreak\code{Preorder} is a logical scalar option with default \code{false}. Its bare form and the explicit value \code{true} select SparseFullBox with default \code{BandWidth=2}. \code{BandWidth} or \code{SparseFullBoxOrder} alone also enables this family. Explicit \code{UseSparseFullBox}\allowbreak\code{Preorder=false} conflicts with either sparse parameter.
  \item \code{BandWidth=w} remains the selected-state property name, while $w$ is implemented as one finite positive tensor-window side length. Flattened matrix bandwidths belong to a different construction. \code{SparseFullBoxOrder=r} accepts scalar shorthand or an $\ell$-element vector and is stored as the $1$-by-$\ell$ absolute Gram order $\vect{r}$. Its default and minimum are $(\lfloor M_1/2\rfloor)$ when $\vect{M}=(M_1)$ and componentwise $\lceil\vect{M}/2\rceil$ otherwise, where $\vect{M}=\code{C.Residual.Degree}$. Width one canonicalizes to actual Direct state after order validation, a width that spans every order axis canonicalizes to actual FullBox state, and intermediate widths select SparseFullBox state.
  \item \code{UseFullBoxPreorder} is a logical scalar option with default \code{false}. Its bare form and the explicit value \code{true} select full-box assembly at the smallest admissible order.
  \item \code{FullBoxOrder=r} accepts scalar shorthand or an $\ell$-element vector and is stored as the $1$-by-$\ell$ absolute order $\vect{r}$, which is distinct from a degree increment. Supplying it by itself enables full-box assembly. When FullBox is enabled, the minimum is $\vect{r}=(\lfloor M_1/2\rfloor)$ for a one-parameter residual with $\vect{M}=(M_1)$, and componentwise $\lceil\vect{M}/2\rceil$ for two or more parameters. Explicitly pairing \code{UseFullBoxPreorder=false} with \code{FullBoxOrder=r} suppresses that automatic selection: \code{C} remains direct and records the normalized row only as inspectable metadata, while assembly remains direct.
  \item P\'olya, Putinar, SparsePutinar, SparseFullBox, and FullBox selection are mutually exclusive and apply only to inequalities. Any recognized certificate option on an equality raises \codeerr{pdlmi}{Unsupported}\allowbreak\code{EqualityCertificate} before clique, width, or order validation. Enabling more than one inequality family raises \codeerr{pdlmi}{Conflicting}\allowbreak\code{Relaxations}.
  \item \code{ValidationMode=mode} accepts scalar text \code{"fast"} or \code{"strict"}, case-insensitively, and defaults to \code{"fast"}. It is transient and discarded after validation. Every certificate selector accepts its own trailing \code{ValidationMode}, and each later call uses its locally supplied mode or the default.
  \item \code{C} is direct coefficient-wise assembly unless one opt-in inequality mode is selected. Comparisons such as \code{lhs >= rhs} are the ordinary user-facing entry point and accept compatible numeric, \code{pdmat}, affine \code{sdpvar}, and \code{pdvar} right-hand sides.
\end{itemize}

The inspectable properties \code{Constraints}, \code{Residual}, and \code{Relation} expose the assembled finite constraints and the original comparison data used for rebuilding. Their set access is private. \code{UsePolya} and \code{PolyaDegree} record the P\'olya state. \code{UsePutinar} and \code{PutinarOrder} record the dense Putinar state. \code{UseSparsePutinar}, \code{SparsePutinarOrder}, and \code{CliqueSize} record the SparsePutinar state. \code{UseSparseFullBoxPreorder}, \code{SparseFullBoxOrder}, and \code{BandWidth} record the SparseFullBox state. \code{UseFullBoxPreorder} and \code{FullBoxOrder} record the FullBox state. A comparison-created Direct object has every selector set to false and every numeric certificate property set to zero. The explicit-false FullBox form is the sole exception because it retains the supplied order in \code{FullBoxOrder}, keeps \code{UseFullBoxPreorder} false, and leaves the stored constraints direct. The Putinar, SparsePutinar, and SparseFullBox selectors reject their corresponding explicit-false and explicit-order combinations.

\section{Assemble Direct Coefficient Constraints}\index{direct assembly}\index{direct coefficient assembly}
\label{sec:pdlmi-direct}

For a \code{pdvar} residual, including equality behavior, each physical cell, local Bernstein coefficient, and rate-vertex row if present creates one stored YALMIP constraint entry. For an ordinary expression with $N_c$ physical cells and $N_b$ Bernstein coefficients per cell, the number of entries is $N_cN_b$. With $N_v$ rate vertices it is $N_cN_bN_v$. A semidefinite-mode entry is one matrix constraint. An entry-wise-mode entry is the column-major vector of scalar matrix entries compared independently. An equality entry is the corresponding direct coefficient equation and may be rectangular. For a coefficient-backed known \code{pdmat} inequality, Direct and P\'olya assembly instead scan the complete numeric coefficient family and store exactly one logical cell containing the global certificate. \code{toYalmip} exports that state as one scalar logical.

The idea is the Bernstein convex-hull property. After orienting the cell residual $\mathcal F^{(\vect{c})}$ as the sign-normalized positive target $S^{(\vect{c})}$, suppress the already-stacked rate-row index and write
\begin{gather*}
S^{(\vect{c})}(\vect{\alpha})=
  \sum_{\vect{i}\in\prod_{s=1}^{\ell}\{0,\ldots,M_s\}}B_{\vect{i}}^{\vect{M}}(\vect{\alpha})
  C^{(\vect{c})}[\vect{i}],
\end{gather*}
where $\vect{M}$ is the assembled residual tensor degree and $\vect{i}\in\prod_{s=1}^{\ell}\{0,\ldots,M_s\}$. The semidefinite direct certificate requires $C^{(\vect{c})}[\vect{i}]\succeq0$ for every physical cell $\vect{c}$ and local label $\vect{i}$, repeated independently for every stored rate row. This condition is sufficient, and feasible residuals may lie outside its certificate set.

For an entry-wise inequality, replace each matrix coefficient by \code{C(:)} and impose the oriented scalar sign on every component. The global classification is made before P\'olya elevation or Gram assembly, so every coefficient and every certificate in one wrapper uses the same mode. Putinar, SparsePutinar, SparseFullBox, and FullBox create one independent scalar Gram certificate for each column-major entry. Direct equality simply imposes \code{C(:) == 0} with an exact zero target and direct equations in place of a positivity certificate. \Cref{sec:certificate-direct} proves the convex-hull implication and separates this sufficient coefficient test from point sampling.

Its stored-constraint count is therefore the number of physical cells times the number of local Bernstein coefficients, with an additional factor for active rate vertices. As stated above, a coefficient-backed known \code{pdmat} inequality instead stores exactly one logical cell containing the global numeric certificate.

\section{Select P\'olya Assembly with \texorpdfstring{\codeplain{usePolya}}{usePolya}}
\index{Polya@P\'olya}\index{usePolya@\texttt{usePolya}}\index{P\'olya certificate}\index{P\'olya elevation}
\label{sec:pdlmi-polya}

With \code{UsePolya=true}, \code{pdlmi} first elevates the stored residual componentwise by $\vect{d}=\code{PolyaDegree}$. For a \code{pdvar} residual it then constrains every elevated local coefficient and stored rate row: if the assembled residual degree is $\vect{M}$, the count is $N_c\prod_{s=1}^{\ell}(M_s+d_s+1)$ for ordinary expressions and $N_cN_v\prod_{s=1}^{\ell}(M_s+d_s+1)$ for rate-row expressions. A coefficient-backed known \code{pdmat} residual instead stores exactly one logical cell containing the global numeric certificate, including after P\'olya elevation. An all-zero increment is valid and has the same coefficient count as Direct. For an entry-wise \code{pdvar} inequality, elevation preserves the global mode and the oriented sign is applied independently to every column-major scalar entry of each elevated coefficient. Equality wrappers reject this method.

\syntaxhead
\begin{lstlisting}[style=dpsyntax]

\section{Select Putinar Assembly with
\texorpdfstring{\codeplain{usePutinar}}{usePutinar}}
\index{Putinar}\index{usePutinar@\texttt{usePutinar}}
\index{Putinar certificate}\index{Putinar order}
\label{sec:pdlmi-putinar}

Putinar is dimension-aware. One parameter uses the exact parity-specific interval form, while two or more parameters use the fixed-order box-specific singleton-generator module. In one parameter, $\vect{M}=(M_1)$ and the default and minimum order vector is $\vect{r}=(\lfloor M_1/2\rfloor)$. In several parameters, the default and minimum are componentwise $\lceil\vect{M}/2\rceil$. Equality wrappers reject Putinar selection.

\syntaxhead
\begin{lstlisting}[style=dpsyntax]
Cputinar = C.usePutinar()
Cputinar = C.usePutinar(r)
Cputinar = C.usePutinar(..., ValidationMode=mode)
\end{lstlisting}

Here \code{r} is scalar shorthand or a direction-wise absolute Bernstein Gram order. The form with the order omitted uses the applicable minimum, and an explicit order must satisfy the same bound. Each physical cell, active rate row, and column-major entry in entry-wise mode receives fresh Gram variables. All PSD blocks precede exact coefficient identities in the stored constraint order. \Cref{sec:certificate-markov-lukacs,sec:certificate-putinar-schmudgen} gives the derivations.

\examplehead
\begin{lstlisting}[style=dpmatlab]
yalmip('clear')
P = pdvar(1, {[0 1]}, Degree=2);
direct = P >= 0;
putinar = direct.usePutinar();
directUsesPutinar = direct.UsePutinar
directOrder = direct.PutinarOrder
directConstraintCount = numel(direct.Constraints)
selectedUsesPutinar = putinar.UsePutinar
selectedOrder = putinar.PutinarOrder
selectedConstraintCount = numel(putinar.Constraints)
\end{lstlisting}

\begin{lstlisting}[style=dpoutput]

  logical
   0
directOrder = 0
directConstraintCount = 3
selectedUsesPutinar =
  logical
   1
selectedOrder = 1
selectedConstraintCount = 5
\end{lstlisting}

For this one-parameter scalar degree-two cell, order one uses the exact even Markov--Luk\'acs form: an unweighted Gram block of dimension two and one generator-weighted block of dimension one, followed by three exact coefficient identities.  The result is identical to \code{direct.useFullBox()}.  Each physical cell and each active rate-vertex row receives independent copies of these PSD blocks and identities.

\ideastep{Anisotropic assembly output} Consider a separate two-parameter target with $\vect{M}=(3,1)$ and absolute order $\vect{r}=(2,1)$. The Putinar specification uses the empty mask and the two singleton generators $g_s=\alpha_s(1-\alpha_s)$, includes every nonnegative basis degree, and matches the elevated target at $2\vect{r}=(4,2)$.

\code{usePutinar} is value-semantic. It rebuilds from the original \code{Residual} and \code{Relation}, replaces any previous family, uses a zero implicit margin, and leaves solver invocation to the caller.

\remarkshead
\begin{enumerate}[leftmargin=*]
  \item Malformed scalar or vector orders raise \codeerr{pdlmi}{InvalidPutinarOrder}. An order below $(\lfloor M_1/2\rfloor)$ for $\vect{M}=(M_1)$, or below componentwise $\lceil\vect{M}/2\rceil$ in two or more parameters, raises \codeerr{pdlmi}{PutinarOrderTooLow}. \item A malformed selector raises \codeerr{pdlmi}{InvalidUsePutinar}. Explicit false plus any supplied order raises \codeerr{pdlmi}{ConflictingPutinarOptions}. \item Simultaneous relaxation families raise \codeerr{pdlmi}{ConflictingRelaxations}. Expression, relation, and option validation in \cref{sec:pdlmi-construction} still applies. Global inequality classification is unchanged: the family is semidefinite only when every original coefficient across all cells and rate rows is square Hermitian. Otherwise the complete family uses independent entry-wise scalar Putinar certificates in MATLAB column-major order.
\end{enumerate}

\section[Select SparsePutinar with \texorpdfstring{\codeplain{useSpPut}}{useSpPut}]{%
Select SparsePutinar with\\[-0.15em] \texorpdfstring{\codeplain{useSpPut}}{useSpPut}}
\index{SparsePutinar}\index{axis-aligned tensor window}\index{tensor window}\index{useSpPut@\texttt{useSpPut}}\index{CliqueSize@\texttt{CliqueSize}}
\label{sec:pdlmi-sparse-putinar}

SparsePutinar applies sliding tensor windows to the active Putinar terms. Each window owns an independent PSD block, and the exact coefficient identities retain their common target degree. A smaller window can reduce the largest PSD block while increasing the number of blocks, so clique size alone provides zero universal ordering of solve time.

\syntaxhead
\begin{lstlisting}[style=dpsyntax]
Csp = C.useSpPut()
Csp = C.useSpPut(b)
Csp = C.useSpPut(b, r)
Csp = C.useSpPut(..., ValidationMode=mode)
\end{lstlisting}

\arghead
\begin{itemize}[leftmargin=*]
  \item \code{b} is one finite positive integer clique size and defaults to two. It is the common requested side length of every tensor window. Graph cliques inferred from matrix sparsity belong to a separate construction.
  \item \code{r} is scalar shorthand or an $\ell$-element direction-wise absolute Putinar Gram order $\vect{r}$. It defaults to $(\lfloor M_1/2\rfloor)$ when $\vect{M}=(M_1)$ and componentwise $\lceil\vect{M}/2\rceil$ in two or more parameters. An explicit order must satisfy the same minimum before endpoint normalization.
  \item \code{mode} is the optional transient \code{"fast"} or \code{"strict"} validation mode. It is case-insensitive and is discarded after validation.
  \item \code{Csp} is a new \code{pdlmi}. An intermediate result sets \code{UseSparsePutinar} to true, stores $r$ in \code{SparsePutinarOrder}, and stores $b$ in \code{CliqueSize}. The source wrapper remains unchanged.
\end{itemize}

\descriptionhead
In one parameter, \code{b=1} returns actual Direct state after order validation. In two or more parameters, \code{b=1} remains SparsePutinar. A size greater than one that spans every active basis returns actual dense Putinar state, while other valid sizes retain SparsePutinar state. Every cell, rate row, and entry-wise matrix entry receives fresh window variables, with PSD blocks stored before coefficient identities. \Cref{sec:certificate-sparse-putinar} gives the window construction and accumulated identities.

\examplehead
\begin{lstlisting}[style=dpmatlab]

directEndpoint = sparse.useSpPut(1, 2);

    sparse.SparsePutinarOrder, sparse.CliqueSize, ...
    sparse.UsePutinar, numel(sparse.Constraints)]
directEndpointState = [directEndpoint.UseSparsePutinar, ...
    directEndpoint.UsePutinar, directEndpoint.CliqueSize, ...
    numel(directEndpoint.Constraints)]
denseEndpointState = [denseEndpoint.UseSparsePutinar, ...
    denseEndpoint.UsePutinar, denseEndpoint.PutinarOrder, ...
    numel(denseEndpoint.Constraints)]
\end{lstlisting}

\begin{lstlisting}[style=dpoutput]

     1     2     2     0     8
directEndpointState = 1×4 double
     0     0     0     5
denseEndpointState = 1×4 double
     0     1     2     7
\end{lstlisting}

The intermediate result has three independent clique-size-two PSD blocks of dimension two followed by five exact coefficient identities. The size-one request returns actual Direct state with five coefficient constraints. The size-three request covers every active Gram basis and returns dense Putinar state with PSD-block dimensions three and two followed by the same five identities.

\ideastep{Anisotropic assembly output} For an independent target with $\vect{M}=(2,4)$, order $\vect{r}=(1,2)$, and clique size $b=2$, each active empty or singleton Putinar term is split into its own overlapping tensor windows. \remarkshead
\begin{enumerate}[leftmargin=*]
  \item \code{useSpPut} rebuilds from the stored \code{Residual} and \code{Relation}. It replaces any earlier P\'olya, Putinar, SparsePutinar, SparseFullBox, or FullBox selection, uses a zero implicit margin, and leaves solver invocation to the caller.
  \item For \code{>=}, coefficient identities match the residual. For \code{<=}, they match its negative. Every physical cell and active rate row receives independent window Gram variables and identities. Entry-wise mode adds an independent scalar certificate for each matrix entry in MATLAB column-major order.
  \item Within each local certificate, all PSD window blocks precede all exact target-coefficient identities. Windows may overlap, and a basis-label pair contributes once through each independent window that contains it.
  \item Invalid clique sizes raise \codeerr{pdlmi}{InvalidCliqueSize}.   \item A malformed selector raises \codeerr{pdlmi}{InvalidUseSparsePutinar}. Explicit false with \code{CliqueSize} or \code{SparsePutinarOrder} raises \codeerr{pdlmi}{ConflictingSparsePutinarOptions}. Co-selection with another family raises \codeerr{pdlmi}{ConflictingRelaxations}. Equality raises \codeerr{pdlmi}{UnsupportedEqualityCertificate} before clique-size or order validation.

\section[Select SparseFullBox with \texorpdfstring{\codeplain{useSpBox}}{useSpBox}]{%
Select SparseFullBox with\\[-0.15em] \texorpdfstring{\codeplain{useSpBox}}{useSpBox}}

\section[Select FullBox with \texorpdfstring{\codeplain{useFullBox}}{useFullBox}]{%
Select FullBox with\\[-0.15em] \texorpdfstring{\codeplain{useFullBox}}{useFullBox}}
\index{FullBox}\index{full-box preordering}\index{useFullBox@\texttt{useFullBox}}
\label{sec:pdlmi-full-box}

FullBox selects the box-specific dense Bernstein--Gram preordering. General-domain SOS parsing belongs to a separate construction. FullBox uses a zero implicit margin and rejects equality wrappers. Every column-major scalar entry in entry-wise mode receives an independent certificate.

\section{Export with \texorpdfstring{\codeplain{toYalmip}}{toYalmip}}

\subsection{Solve with YALMIP}
\label{sec:pdlmi-solver-use}

Solver settings and the call to \code{optimize} belong to the caller's YALMIP workflow. After \code{toYalmip}, validate the returned status before retaining an objective or recovered coefficient data:

\begin{lstlisting}[style=dpsyntax]
opts = sdpsettings("solver", solverName, "verbose", 0);
sol = optimize([C1.toYalmip, C2.toYalmip], objective, opts);
assert(sol.problem == 0, sol.info)
objectiveValue = value(objective);
\end{lstlisting}

An optimized certificate value requires \code{problem == 0}. Numerical, unknown, aborted, memory, and space-exhaustion statuses are inconclusive about both the original continuous problem and the value of $\gamma$.
