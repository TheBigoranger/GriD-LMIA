\section{From the Residual to Finite Certificates}
\label{sec:cellwise-solver-path}
\index{residual}\index{strictness margin}\index{certificate}

Continue with the one-dimensional two-cell, degree-two objects introduced at the opening of the Bernstein section and choose \(\varepsilon=10^{-6}\). The comparison below is the MATLAB form of \cref{eq:running-residual}.

\begin{lstlisting}[style=dpmatlab]
epsilon = 1e-6;
residual = P - H;
direct = residual >= epsilon * eye(2);

residualDegree = residual.Degree
directConstraintCount = numel(direct.Constraints)
\end{lstlisting}

\begin{lstlisting}[style=dpoutput]
residualDegree = 2
directConstraintCount = 6
\end{lstlisting}

The overloaded comparison creates a \code{pdlmi}. It stores the original residual and relation, orients the inequality as a positive target, and selects Direct by default. There are two physical cells and three degree-two coefficients per cell, hence six local matrix constraints. The shared face is visited once from each cell because certification is cell-local, even though both visits contain the same boundary decision handle.

\subsection{Direct coefficient test}

For one cell, write the positive target as
\[
    T^{(c)}(\rho)=\sum_{i=0}^{2}B_i^2(\alpha_c)T^{(c)}[i].
\]
Direct imposes \(T^{(c)}[i]\succeq0\) for every cell and every local label. Since the basis is nonnegative and sums to one, these coefficient inequalities imply \(T^{(c)}(\rho)\succeq0\) throughout the cell. This implication is the certificate: a positive matrix polynomial may still have an indefinite Bernstein coefficient, so Direct failure is not a converse infeasibility test.

\subsection{Alternative certificates}

Four opt-in methods rebuild a certificate from the same original residual and comparison:

\begin{lstlisting}[style=dpmatlab]
polya = direct.applyPolya(1);
putinar = direct.applyPutinar();
sparseEndpoint = direct.applySparseFullBoxPreorder(2);
fullBox = direct.applyFullBoxPreorder();
\end{lstlisting}

For this one-parameter degree-two residual, the default absolute SparseFullBox order is \(r=1\). The requested width \(b=2=r+1\) therefore reaches the dense endpoint, so \code{sparseEndpoint} returns actual FullBox state rather than retained SparseFullBox state. Retained intermediate sparse state requires \(1<b<r+1\); the higher-order and two-dimensional examples in \cref{sec:pdlmi-sparse-full-box} show that case.

P\'olya first elevates the local Bernstein representation by the requested nonnegative degree increment, then applies the coefficient test to the elevated coefficients. \code{applyPutinar}, \code{applySparseFullBoxPreorder}, and \code{applyFullBoxPreorder} use fixed-order Bernstein--Gram representations. Their order arguments are absolute Gram orders, not degree increments. In one parameter, Putinar and FullBox use the same parity-specific interval representation; SparseFullBox width one normalizes to Direct, while a width large enough for dense support normalizes to FullBox. In two or more parameters, Putinar uses the implemented singleton-generator box module, SparseFullBox restricts Gram support through overlapping tensor windows, and FullBox uses the complete box preordering.

Each selector is a value-class operation: it returns a new wrapper, leaves \code{direct} unchanged, and replaces any earlier certificate selection by rebuilding from the stored original residual. None of the selectors adds a positivity margin or calls a solver. The complete order, width, normalization, and validation rules appear in \cref{sec:pdlmi}; the certificate formulas and their implemented boundaries appear in \cref{sec:certificate-modeling-choices,sec:certificate-boundary}.

\subsection{Export and interpretation}

\code{toYalmip} returns the finite constraints stored by the selected wrapper. Solver choice, objectives, and status interpretation remain explicit user decisions.

\needspace{9\baselineskip}
\begin{lstlisting}[style=dpmatlab]
F = direct.toYalmip();
opts = sdpsettings('solver', 'mosek', 'verbose', 0);
sol = optimize(F, [], opts);
assert(sol.problem == 0, sol.info)
solvedP = value(P);
\end{lstlisting}

Only a successful solver status supports recovery of a feasible numerical decision. The returned \code{solvedP} preserves the grid, degree, matrix shape, and cell ordering while replacing symbolic coefficient payloads by their numerical values. If a selected certificate is infeasible or the solver reports a numerical or unknown status, do not interpret that result as proof that the original continuum problem is infeasible.

When connecting the mathematical model to the implementation, write \(\boldsymbol\nu=\dot{\boldsymbol\rho}\) and identify the stored rate box \(\mathcal R\) with \(\mathcal V\). The \code{RateBounds} rows contain \([\underline v_s,\overline v_s]\), and \code{rhodiff} constructs cell-local derivative data with one stored row per vertex \(\boldsymbol\nu\in\operatorname{vert}(\mathcal R)\). Traversing all rate vertices is exact for the affine rate dependence in \cref{eq:general-pdlmi}; Direct or a selected Gram certificate is subsequently applied to every stored row over every parameter cell. Nonaffine rate dependence does not inherit this exact vertex argument.
