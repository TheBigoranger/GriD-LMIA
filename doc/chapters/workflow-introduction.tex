\chapter[From LPV Models to Cellwise Bernstein Data]{\texorpdfstring{From LPV Models to\\Cellwise Bernstein Data}{From LPV Models to Cellwise Bernstein Data}}
\label{sec:canonical-pdlmi}
\label{sec:bernstein-motivation}

This chapter fixes the vocabulary and data model used throughout the manual.
It begins with a continuous control inequality, separates the physical grid
from local polynomial labels, and ends at the exact cell-local Bernstein data
consumed by the algebra in \cref{sec:cellwise-solver-path}.

\section{LPV Systems and Parameter-Dependent LMIs}

A \emph{linear parameter-varying (LPV) system}\index{LPV system} is a linear
state-space model whose matrices depend on a measurable scheduling vector
\(\boldsymbol\rho(t)=(\rho_1(t),\ldots,\rho_\ell(t))\).  For the autonomous
model used here,
\[
  \dot x(t)=A\bigl(\boldsymbol\rho(t)\bigr)x(t),
\]
the state equation is linear in \(x\), while the scheduling vector selects the
current matrix from the known family \(A(\boldsymbol\rho)\).  The admissible
scheduling values lie in a compact parameter set \(\mathcal P\), and a
rate-dependent problem also bounds
\(\dot{\boldsymbol\rho}(t)\in\mathcal V\).

A \emph{parameter-dependent linear matrix inequality} (PD-LMI)\index{PD-LMI}
asks a matrix inequality to hold for every
\(\boldsymbol\rho\in\mathcal P\).  When derivatives of decision functions
enter through the scheduling rate, this manual calls it a
\emph{differentiable parameter-dependent LMI} (DPD-LMI)\index{DPD-LMI}.  A
standard LPV Lyapunov model seeks a symmetric matrix
\(P(\boldsymbol\rho)\) such that
\begin{align}
  P(\boldsymbol\rho)&\succeq I,
    \label{eq:canonical-positive}\\
  \dot P(\boldsymbol\rho,\dot{\boldsymbol\rho})
    +P(\boldsymbol\rho)A(\boldsymbol\rho)
    +A(\boldsymbol\rho)^{\mathsf T}P(\boldsymbol\rho)
    &\preceq-\varepsilon I.
    \label{eq:lpv-spine}
\end{align}
After known data are fixed, every term must remain affine in the decision
coefficients.  Removing \(\dot P\), or fixing
\(\dot{\boldsymbol\rho}=0\), recovers an ordinary PD-LMI.  The package inserts
no hidden strictness margin: the displayed \(\varepsilon I\) belongs to the
user's model.

\section{The Chain Rule in a DPD-LMI}

The dot on \(P\) is a time derivative along the scheduling trajectory, not a
new independent matrix.  The multivariable chain rule is
\[
  \dot P\bigl(\boldsymbol\rho(t)\bigr)
  =\frac{dP}{dt}
  =\sum_{s=1}^{\ell}
    \frac{\partial P}{\partial\rho_s}
      \bigl(\boldsymbol\rho(t)\bigr)\dot\rho_s(t).
\]
Thus the DPD-LMI depends on both the spatial derivatives of the decision
matrix and the admissible scheduling rates.  The package first differentiates
the cell polynomial in each parameter direction and then enumerates the
vertices of the rate box.  This is the role of \code{rhodiff}; it does not
differentiate with respect to time symbolically and it does not create a new
physical grid.

For the running example, \(P\) is \(2\)-by-\(2\),
\(\rho\in[0,1]\), \(\dot\rho\in[-1,1]\), and
\(\varepsilon=10^{-6}\).  In one parameter the sum reduces to
\(\dot P=(\partial P/\partial\rho)\dot\rho\).

\section{Grid the Scheduling-Parameter Space}

Choose a one-dimensional physical grid
\[
  \mathcal G_s=
  \{\rho_s^{(1)},\ldots,\rho_s^{(k_s)}\}
\]
in every parameter direction \(s\).  The full tensor grid is
\(\mathcal G=\mathcal G_1\times\cdots\times\mathcal G_\ell\).  It contains
\(\prod_s k_s\) physical nodes and partitions \(\mathcal P\) into
\(\prod_s(k_s-1)\) physical hypercubes.  A hypercube is identified by the
one-based multi-index
\(\mathbf c=(c_1,\ldots,c_\ell)\) and has domain
\[
  \mathcal H_{\mathbf c}
  =\prod_{s=1}^{\ell}
   [\rho_s^{(c_s)},\rho_s^{(c_s+1)}].
\]
Inside that hypercube, the forward local coordinate is
\[
  \alpha_s=
  \frac{\rho_s-\rho_s^{(c_s)}}
       {\rho_s^{(c_s+1)}-\rho_s^{(c_s)}}\in[0,1].
\]
Physical-node indices and components of \(\mathbf c\) are one-based.  They
identify geometry, not coefficient positions.

\section{Physical Hypercubes and Local Bernstein Labels}

On one selected hypercube, a tensor-product polynomial of degree \(m\) is
\[
 C^{(\mathbf c)}(\boldsymbol\rho)=
 \sum_{\mathbf i\in\{0,\ldots,m\}^{\ell}}
 \left(\prod_{s=1}^{\ell}B_{i_s}^{m}(\alpha_s)\right)
 C^{(\mathbf c)}[\mathbf i],
\]
where
\[
  B_i^m(\alpha)=\binom mi(1-\alpha)^{m-i}\alpha^i.
\]
The local Bernstein label \(\mathbf i\) is zero-based.  It chooses one matrix
coefficient inside the already selected physical hypercube; it is not another
physical point.  The nonnegative basis functions sum to one, so the polynomial
value lies in the convex hull of its coefficient matrices.  Exact elevation,
multiplication, and differentiation operate on these local rows without
changing the physical identity \(\mathbf c\).

The traversal order used by \code{cells}, \code{lbls}, \code{coeffs}, and
rate-vertex rows varies later dimensions fastest.  In two dimensions,
\code{lbls()} therefore lists
\([0,0],[0,1],\ldots,[0,m],[1,0],\ldots,[m,m]\).

\section{What One Hypercube Stores}
\label{sec:one-hypercube-storage}

The first two-dimensional example uses
\(\mathcal G_1=\{0,0.5,1\}\),
\(\mathcal G_2=\{0,1\}\), and degree two:

\begin{lstlisting}[style=dpmatlab]
grid2 = {[0 .5 1], [0 1]};
A2 = pdmat(grid2, @(rho1,rho2) ...
    [1+rho1+rho2, rho1*rho2; ...
     rho1*rho2,   2+rho1^2], Degree=2);
physicalCells = A2.cells()
localLabels = A2.lbls()
secondCellCoefficients = A2.coeffs([2 1])
sameLeaf = A2.LocalValues{2}{1}
\end{lstlisting}

The grid has two physical hypercubes.  The highlighted one below is
\(\mathbf c=(2,1)\), whose domain is
\([0.5,1]\times[0,1]\).  Selecting it through
\code{A2.coeffs([2 1])} reaches the same nested storage leaf as
\code{A2.LocalValues{2}{1}}.

\section{Continuity Across Shared Faces}

Independent cell polynomials would not necessarily agree on a grid boundary.
The package instead shares the complete Bernstein coefficient face between
adjacent continuous cells.  On a face, the tensor polynomial depends only on
that face's coefficients, so sharing them gives \(C^0\) continuity.

For a one-dimensional degree-two example,
\[
  C^{(1)}[2]=C^{(2)}[0]
\]
is the common value at the interface.  The two interior coefficients
\(C^{(1)}[1]\) and \(C^{(2)}[1]\) remain independent.  Derivatives on the two
sides need not agree: the representation guarantees value continuity and,
on a finite compact grid, global Lipschitz regularity, but not \(C^1\)
continuity.  Derivative data produced by \code{rhodiff} are deliberately
cell-local and may therefore be discontinuous.
