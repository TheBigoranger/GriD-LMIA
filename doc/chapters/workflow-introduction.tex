\chapter[From LPV Models to Finite Solver Constraints]{\texorpdfstring{From LPV Models to\\Finite Solver Constraints}{From LPV Models to Finite Solver Constraints}}
\label{sec:canonical-pdlmi}
\label{sec:bernstein-motivation}

This chapter introduces the purpose, object model, and complete solution path of the package. It begins with a continuous LPV control inequality, separates the physical grid from local polynomial labels, and ends with finite YALMIP constraints and recovery of the solved parameter-dependent matrix.

\section{Motivation: LPV Systems and Parameter-Dependent LMIs}

Many systems are usefully linear only after their operating condition is made explicit. An aircraft changes with altitude and speed, a chemical process changes with temperature and concentration, and an autonomous vehicle changes lane with forward speed and tire cornering conditions. Treating those conditions as unrelated LTI models discards their shared structure. Requiring one constant Lyapunov matrix or one constant stability criterion for all cases can be equally unsatisfactory, as the resulting test is often unnecessarily conservative.

A \emph{linear parameter-varying (LPV) system}\index{LPV system} keeps the linear state-space structure while allowing its known matrices to depend on a measurable scheduling vector \(\boldsymbol\rho(t)=(\rho_1(t),\ldots,\rho_\ell(t))\in\mathcal P\subset \mathbb{R}^\ell\). For example, an autonomous model is written as
\[
    \dot x(t)=A\bigl(\boldsymbol\rho(t)\bigr)x(t),
\]
where \(x\) is the state vector and \(\boldsymbol\rho\) selects the current parameter of the known matrix family \(A(\boldsymbol\rho)\). The central question is therefore not whether each frozen model works in isolation, but whether one structured stability condition proves the required property throughout the full parameter set \(\mathcal P\).

A \emph{differentiable parameter-dependent linear matrix inequality} (DPD-LMI)\index{DPD-LMI} supplies that condition by allowing the decision matrix itself to vary with \(\boldsymbol\rho\). A standard LPV Lyapunov construction seeks a symmetric \(P(\boldsymbol\rho)\) such that the following inequalities hold throughout \((\rho,\dot{\rho}) \in \mathcal{P}\times \mathcal{V}\):
\begin{align}
P(\boldsymbol\rho) & \succeq I,
\label{eq:canonical-positive}               \\
    \dot P(\boldsymbol\rho,\dot{\boldsymbol\rho})
    +P(\boldsymbol\rho)A(\boldsymbol\rho)
    +A(\boldsymbol\rho)^{\mathsf T}P(\boldsymbol\rho)
    & \preceq-\varepsilon I.
\label{eq:lpv-spine}
\end{align}
The first inequality keeps the Lyapunov function \(V(t)=x^{\top}(t) P(\boldsymbol\rho(t))x(t)\) positive definite, while the second requires $\dot V$ to decrease along every admissible scheduling trajectory. When \(\boldsymbol\rho\) changes with time, the time derivative term \(\dot P\) matters. On the other hand, if \(\boldsymbol\rho\) represents uncertainty of the system, which does not vary with respect to the time, removing \(\dot P\), i.e., fixing \(\dot{\boldsymbol\rho}=0\), recovers an ordinary  \emph{parameter-dependent linear matrix inequality} (PD-LMI)\index{PD-LMI}. After known data are fixed, every term must remain affine in the decision coefficients, and the displayed \(\varepsilon I\) remains an explicit user choice rather than a hidden package margin.

\section{Package roles and the end-to-end path}

The package starts after the user has chosen an LPV model, a parameter box, any scheduling-rate bounds, and the matrix inequality to certify. Its role is to represent the known and decision matrices, convert the parameter continuum into finite certificate constraints, and hand those constraints to YALMIP. It does not generate the plant or controller structure, choose an objective or SDP solver, or interpret solver diagnostics on the user's behalf.

The main objects follow the same four-stage path used in the rest of the manual:
\begin{enumerate}
    \item \code{pdmat} stores known parameter-dependent matrices, while \code{pdvar} creates continuous parameter-dependent decision matrices on a physical grid. Both inherit grid, degree, label, and cell-local storage mechanics from the backend class \code{pdbase}; ordinary users normally begin with \code{pdmat} and \code{pdvar}, not \code{pdbase}. \item Matrix operations form an affine cell-local residual. When scheduling-rate terms are present, \code{rhodiff} differentiates a \code{pdvar} on each cell and stores one derivative row for every rate-box vertex. \item A comparison such as \code{residual <= 0} creates a \code{pdlmi}. Direct Bernstein-coefficient constraints are the default; \code{applyPolya}, \code{applyPutinar}, and \code{applyFullBoxPreorder} replace that selection with an implemented opt-in certificate. \item \code{toYalmip} exports the stored finite constraints. The user calls YALMIP \code{optimize} with an explicit objective and solver configuration, checks the returned diagnostics, and calls \code{value} to recover solved coefficient data.
\end{enumerate}

Two finite reductions in this path have different logical status. Traversing all rate-box vertices is exact when the residual is affine in \(\dot{\boldsymbol\rho}\). By contrast, the selected Bernstein or Bernstein--Gram certificate supplies a finite sufficient condition over the remaining \(\boldsymbol\rho\)-continuum; failure of that certificate does not prove that the original continuous inequality is infeasible. The mathematical comparison in \cref{sec:certificate-five-choices,sec:certificate-boundary} separates the implemented certificate choices from changes to the model itself. The next four sections explain the representation behind these reductions, and \cref{sec:cellwise-solver-path} executes the complete path in MATLAB.

\section{The Chain Rule in a DPD-LMI}
\index{chain rule}\index{parameter rate}\index{rate vertex}\index{rate row}

The dot on \(P\) is a time derivative along the scheduling trajectory, not a new independent matrix. Applying the multivariable chain rule gives
\[
    \dot P\bigl(\boldsymbol\rho(t)\bigr)
=\frac{dP}{dt} =\sum_{s=1}^{\ell}
    \frac{\partial P}{\partial\rho_s}
    \bigl(\boldsymbol\rho(t)\bigr)\dot\rho_s(t).
\]
Write \(\boldsymbol\nu=\dot{\boldsymbol\rho}\) and give every scheduling direction independent finite rate bounds,
\[
    \mathcal V
=\prod_{s=1}^{\ell}[\underline\nu_s,\overline\nu_s].
\]
For a residual that is affine in \(\boldsymbol\nu\), the rate box is handled exactly by traversing its \(2^\ell\) lower/upper vertices \(\boldsymbol v^{(r)}\). The coefficient-level differentiation and rate-row construction are derived in \cref{sec:bernstein-differentiation}. Thus, rather than retaining a rate continuum, the rate-dependent inequality can be written in the block-diagonal form
\begin{gather}
\label{eq:rate-vertex-block-diagonal}
\operatorname{diag}_{r=1}^{2^\ell}
    \mathcal F\bigl(\boldsymbol\rho,\boldsymbol v^{(r)}\bigr)
    \prec 0,
    \qquad \boldsymbol\rho\in\mathcal P.
\end{gather}

Each diagonal block is the residual at one rate vertex.  The remaining continuum is only the scheduling parameter \(\boldsymbol\rho\), which the package treats cellwise with its Bernstein certificates.

We therefore focus on the following general DPD-LMI.
\keyequation{General form of the differentiable parameter-dependent LMI}{%
\begin{equation}
  \mathcal F(\boldsymbol\rho,\dot{\boldsymbol\rho})
  = \sum_{i=1}^{N} R_i(\boldsymbol\rho)
  \sum_{j=1}^{\ell}
  \frac{\partial x_i}{\partial\rho_j}(\boldsymbol\rho)
  \dot\rho_j
  + F_0(\boldsymbol\rho)
  + \sum_{i=1}^{N} F_i(\boldsymbol\rho)x_i(\boldsymbol\rho)
  \prec 0, \qquad \forall (\boldsymbol\rho,\dot{\boldsymbol\rho}) \in\mathcal P\times\mathcal V.
\label{eq:general-dpdlmi}
\end{equation}
} Here \(R_i\), \(F_0\), and \(F_i\) are known matrix functions, while the \(x_i\) are parameter-dependent decision functions. The affine dependence on \(\dot{\boldsymbol\rho}\) reduces exactly to the finite rate vertices in \cref{eq:rate-vertex-block-diagonal}, but \(\boldsymbol\rho\in\mathcal P\) remains a continuum. The construction is dimension-generic in \(\ell\), subject to the cost of the resulting tensor data. The package handles the remaining continuum by representing each \(x_i\) as a continuous piecewise-polynomial function on a physical grid, with cell-local tensor-product Bernstein coefficients.

Setting \(R_i\equiv0\) for every \(i\) (collectively, \(R=0\)) removes the derivative term and recovers an ordinary PD-LMI.

\section{Grid the Scheduling-Parameter Space}
\index{physical grid}\index{physical node}\index{physical hypercube}\index{tensor grid}

The package currently considers only an axis-aligned box parameter domain,
\[
    \mathcal P=\prod_{s=1}^{\ell}[\underline\rho_s,\overline\rho_s].
\]
This restriction is deliberate, as a compact box is easy to partition into hypercubes for cellwise modelling. General polytopic or curved parameter domains are outside the implemented model. Gridding starts independently in each parameter direction. For each direction, choose the following physical grid
\[
    \mathcal G_s=
    \{\underline{\rho}_s=\rho_s^{(1)},\ldots,\rho_s^{(k_s)}=\overline{\rho}_s\},\qquad s=1,\ldots,\ell.
\]
The full tensor grid is \(\mathcal G=\mathcal G_1\times\cdots\times\mathcal G_\ell\).  It contains \(\prod_{s=1}^{\ell} k_s\) physical nodes and partitions \(\mathcal P\) into \(\prod_{s=1}^{\ell}(k_s-1)\) physical hypercubes.  A hypercube is identified by the  $\ell$-dimensional multi-index \(\mathbf c=(c_1,\ldots,c_\ell)\); \cref{sec:bernstein-tensor-grids} gives the exact physical-grid and local-label conventions:
\begin{gather}
    \label{eq:physical-hypercube}
    \mathcal H_{\mathbf c}=\prod_{s=1}^{\ell} [\rho_s^{(c_s)},\rho_s^{(c_s+1)}].
\end{gather}

\section{Desired Behavior Across Cell Boundaries}
\label{sec:desired-cross-cell-behaviour}
\index{shared face}\index{continuity}\index{Lipschitz regularity}

The package represents coefficient-backed known data and decision matrices by local polynomials, so products, degree elevation, and differentiation can be performed one physical cell at a time. A Lyapunov matrix or comparable decision function must not jump when the scheduling trajectory crosses a shared face, so \code{pdvar} guarantees global \(C^0\) continuity. It does not require \(C^1\) continuity, that is, one-sided derivatives may differ, and \code{rhodiff} retains the corresponding cell-local derivative data\index{derivative data}. Known \code{pdmat} data are different: the object records whether adjacent numeric faces match, but it preserves explicitly supplied discontinuous local data rather than adding decision constraints to repair them.

A monomial parameterization makes the additional continuity condition explicit.  For two adjacent one-dimensional cells, write
\[
    A^{(c)}(\alpha_c)=\sum_{i=0}^{m}\alpha_c^i A_i^{(c)},
    \qquad \alpha_c\in[0,1].
\]
At their shared physical node, \(\alpha_1=1\) in the left cell and \(\alpha_2=0\) in the right cell.  Enforcing \(C^0\) continuity therefore requires the extra matrix equality
\[
    \underbrace{\sum_{i=0}^{m}A_i^{(1)}}_{A^{(1)}(1)}
    =\underbrace{A_0^{(2)}}_{A^{(2)}(0)}.
\]
When \(\ell>1\), equality along a shared face is a polynomial identity in the tangential coordinates and produces a corresponding family of linear coefficient equalities. The number of such conditions grows with the polynomial degree and the number of shared faces.

The right side of \cref{fig:shared-face-lipschitz} shows the intended behaviour: the two polynomial pieces share their boundary value, while their one-sided slopes remain different. A globally \(C^0\), piecewise-polynomial matrix function on the compact parameter box is Lipschitz. At a shared face, its Clarke generalized derivative is the convex hull of the limiting derivatives from the adjacent cells. The package consequently imposes \cref{eq:general-dpdlmi} using the relevant cellwise derivative and rate-vertex data without claiming that the derivative itself is globally continuous.

\section{Bernstein Basis and Cell-Local Storage}
\label{sec:continuous-bernstein-representation}
\index{cell-local storage}\index{local Bernstein label}

For its cell-local polynomial representation, the package uses the Bernstein basis rather than the monomial basis in the preceding comparison. Bernstein endpoint identities expose each face polynomial directly through its face coefficients; shared decision storage can therefore impose \(C^0\) continuity without adding separate cross-cell equalities. Inside a physical hypercube \cref{eq:physical-hypercube}, the forward local coordinate in direction \(s\) is
\[
    \alpha_s=
    \frac{\rho_s-\rho_s^{(c_s)}}
    {\rho_s^{(c_s+1)}-\rho_s^{(c_s)}}\in[0,1].
\]
On one local coordinate \(\alpha\in[0,1]\), the normalized degree-\(m\) Bernstein basis is
\[
    B_i^m(\alpha)=\binom mi(1-\alpha)^{m-i}\alpha^i,
    \qquad i=0,\ldots,m.
\]
The basis functions are nonnegative and sum to one.  The first four nonnegative degrees are
\[
\begin{aligned}
    m=0:\quad
    &B_0^0=1                 &
    &\\
    m=1:\quad
      &B_0^1=1-\alpha,                 &
      &B_1^1=\alpha,\\
    m=2:\quad
      &B_0^2=(1-\alpha)^2,             &
      &B_1^2=2(1-\alpha)\alpha,        &
      &B_2^2=\alpha^2,\\
    m=3:\quad
      &B_0^3=(1-\alpha)^3,             &
      &B_1^3=3(1-\alpha)^2\alpha,      &
      &B_2^3=3(1-\alpha)\alpha^2,      &
      &B_3^3=\alpha^3.
\end{aligned}
\]
In \(\ell\) parameter directions, the package uses the tensor-product expansion
\[
    C^{(\mathbf c)}(\boldsymbol\rho)=
    \sum_{\mathbf i\in\{0,\ldots,m\}^{\ell}}
    \left(\prod_{s=1}^{\ell}B_{i_s}^{m}(\alpha_s)\right)
    C^{(\mathbf c)}[\mathbf i].
\]
The matrix value is a convex combination of the local coefficient matrices. Exact degree elevation, multiplication, and differentiation operate on those coefficients without changing the identity of the physical cell. The detailed formulas appear in \cref{sec:bernstein-higher-degree,sec:bernstein-degree-elevation,sec:bernstein-product-math,sec:bernstein-differentiation}.

\subsection{Physical nodes, local labels, and continuity by storage}

The two index systems have different meanings:
\begin{itemize}
    \item the physical node \(\rho_s^{(j)}\) and the cell component \(c_s\) are one-based and identify geometry; \item the local Bernstein label \(i_s\in\{0,\ldots,m\}\) is zero-based and selects one coefficient inside an already chosen cell.
\end{itemize}
A degree-\(m\) tensor polynomial stores \((m+1)^\ell\) local coefficient positions per physical cell.  These positions are not another grid of point samples.  The traversal order used by \code{cells}, \code{lbls}, \code{coeffs}, and rate-vertex rows varies later dimensions fastest; in two dimensions, \code{lbls()} lists \([0,0],[0,1],\ldots,[0,m],[1,0],\ldots,[m,m]\). The general tensor ordering is defined in \cref{sec:bernstein-tensor-grids}.

The endpoint identities \(B_0^m(0)=1\) and \(B_m^m(1)=1\) make continuity easy to encode in coefficient data. For a \code{pdvar}, adjacent cells reuse the same YALMIP decision handles on their common face; in one dimension, \(C^{(1)}[m]\) and \(C^{(2)}[0]\) are the same decision matrix. Tensor cells similarly share every handle on a common face, so continuity requires no later equality constraint. For a coefficient-backed \code{pdmat}, \code{IsContinuous} instead reports whether the two numeric face-coefficient sets agree; explicitly mismatched local data remain cell-local and produce a warning.

\subsection{A two-dimensional storage example}
\label{sec:one-hypercube-storage}

The first two-dimensional example uses \(\mathcal G_1=\{0,0.5,1\}\), \(\mathcal G_2=\{0,1\}\), and degree two:

\begin{lstlisting}[style=dpmatlab]
grid2 = {[0 .5 1], [0 1]};
A2 = pdmat(grid2, @(rho1,rho2) ...
    [1+rho1+rho2, rho1*rho2; ...
        rho1*rho2,   2+rho1^2], Degree=2);
physicalCells = A2.cells()
localLabels = A2.lbls()
secondCellCoefficients = A2.coeffs([2 1])
sameLeaf = A2.LocalValues{2}{1}
\end{lstlisting}

The grid has two physical hypercubes. The highlighted one below is \(\mathbf c=(2,1)\), whose domain is \([0.5,1]\times[0,1]\). Selecting it through \code{A2.coeffs([2 1])} reaches the same nested storage leaf as \code{A2.LocalValues{2}{1}}. The figure lists the nine matrices in \code{A2.lbls()} order, with \(i_1\) varying more slowly than \(i_2\).
