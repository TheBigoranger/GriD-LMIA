<nav class="manual-trail"><a href="/GriD-LMIA/documents/">Documents</a><span>/</span><a href="/GriD-LMIA/documents/reference/pdvar/">pdvar</a><span>/</span><span>storage and evaluation</span></nav>

These methods are implemented by `pdbase` and remain complete public
`pdvar` behavior. They preserve YALMIP expressions, variable identities,
continuity metadata, and derivative rate-row order.

The physical-cell tree, local tensor labels, and traversal functions are the
same as in the
[`pdmat Storage` explanation](/GriD-LMIA/documents/reference/pdmat/storage-and-elevation/).
For `pdvar`, the leaf at cell $\vect c$ and label $\vect i$ stores
the symbolic matrix $X^{(\vect c)}[\vect i]$:

$$
\begin{aligned}
\operatorname{LocalValues}_{\vect c}[\vect i]
&=X^{(\vect c)}[\vect i],\\
X^{(\vect c)}[\vect i]
&\in\operatorname{Aff}(\texttt{sdpvar}).
\end{aligned}
$$

## <span id="pdvar-cells"></span>`cells`

```matlab
cellSubscripts = cells(P)
```

Returns one tensor-grid cell subscript row per physical cell.

## <span id="pdvar-coeffs"></span>`coeffs`

```matlab
symbolicCoefficients = coeffs(P,cellSubscript)
```

For an ordinary expression, returns a `1 × ncoeff(P)` cell row of numeric or
`sdpvar` matrices. For `D = rhodiff(P)`, returns a
`D.NumRateRows × ncoeff(D)` table: every distinct rate vertex is a separate row
and every row remains distinct. Bad selectors raise `pdbase:InvalidCellSubs`.

## <span id="pdvar-lbls"></span>`lbls`

```matlab
labels = lbls(P)
```

Returns the local tensor Bernstein labels in coefficient-column order.

## <span id="pdvar-ncell"></span>`ncell`, <span id="pdvar-ncoeff"></span>`ncoeff`, and <span id="pdvar-npar"></span>`npar`

```matlab
physicalCellCount = ncell(P)
coefficientColumns = ncoeff(P)
parameterCount = npar(P)
```

The counts describe the physical tree and label axes, independently of matrix entries or
rate rows.

```matlab
yalmip('clear')
P = pdvar(2, {[0 1 2], [10 20]}, "symmetric", Degree=[2 2]);
cellSubscripts = P.cells()
counts = [P.ncell() P.ncoeff() P.npar()]
coefficientShape = size(P.coeffs([1 1]))
```

```text
cellSubscripts =
     1     1
     2     1

counts =
     2     9     2

coefficientShape =
     1     9
```

## <span id="pdvar-elevate"></span>`elevate`

```matlab
Q = elevate(P,degreeIncrement)
Q = P.elevate(degreeIncrement)
```

Returns a `pdvar` with higher Bernstein degree and the same underlying YALMIP
variables, grid, payload shape, continuity flag, `ContainsDecision`,
`NumRateRows`, `RateBounds`, and row ordering. It preserves the existing
independent decision field.

## <span id="pdvar-evaluate"></span>`evaluate`

```matlab
symbolicValue = evaluate(P,point)
rateValues = evaluate(D,point)
```

`point` is a finite in-bounds vector with one coordinate per parameter.
Ordinary `pdvar` returns one interpolated numeric/`sdpvar` matrix while
preserving the current `assign` state. A derivative `pdvar` returns a
`1 × D.NumRateRows` cell array, with one affine expression per distinct rate
row.

For the selected physical cell, ordinary evaluation is the symbolic Bernstein
sum

$$
\begin{aligned}
\vect\alpha
&:=\phi_{\vect c}^{-1}(\vect\rho),\\
P^{(\vect c)}(\vect\rho)
&=\sum_{\vect i\in\prod_{s=1}^{\ell}\{0,\ldots,m_s\}}\\
&\quad X^{(\vect c)}[\vect i]\,
B_{\vect i}^{\vect m}(\vect\alpha).
\end{aligned}
$$

This is the same basis evaluation illustrated on
[`pdmat evaluate`](/GriD-LMIA/documents/reference/pdmat/evaluate/).
Only the stored coefficients and returned value are symbolic.

Interior grid boundaries use the cell on the right, including discontinuous
derivative rows. The last global boundary uses the last cell. Numeric and
symbolic payload types are preserved.

```matlab
yalmip('clear')
P = pdvar(1, {[0 1]}, Degree=1);
Q = P.elevate(2);
classes = [string(class(P)) string(class(Q))]
degrees = [P.Degree Q.Degree]
ordinary = P.evaluate(0.25);
ordinaryType = string(class(ordinary))
```

```text
classes =
  1x2 string array
    "pdvar"    "pdvar"

degrees =
     1     3

ordinaryType =
    "sdpvar"
```

## Validation And Errors

Invalid elevation uses `pdbase:InvalidDegreeIncrement`. Invalid points use
`pdvar:InvalidPoint`. Out-of-bounds points use
`pdvar:PointOutOfBounds`. Evaluation interpolates stored expressions directly.
YALMIP retains ownership of assignment and solution recovery, while derivative
rows remain separate.
