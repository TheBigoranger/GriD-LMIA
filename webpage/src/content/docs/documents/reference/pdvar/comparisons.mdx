## Purpose

Overloaded `<=`, `>=`, and `==` promote compatible operands, store `lhs-rhs` as a `pdvar` residual, and return a [`pdlmi`](/PD-LMI-package/documents/reference/pdlmi/) wrapper. They assemble finite constraints; they do not choose a solver or call `optimize`.

## Syntax

```matlab
Cneg = lhs <= rhs;
Cpos = lhs >= rhs;
Ceq  = lhs == rhs;
```

`lhs` and `rhs` may be compatible numeric, `pdmat`, affine `sdpvar`, or `pdvar` values. Ordinary operands are promoted through subtraction. Derivative expressions retain their rate-vertex rows.

## <span id="pdvar-comparison-le"></span><span id="pdvar-comparison-ge"></span>Inequalities: `le`/`<=` and `ge`/`>=`

Each inequality is classified **once for the complete original residual**:

1. Scan every original coefficient in every physical cell and active rate row.
2. Use semidefinite meaning only when every coefficient is square and Hermitian. Numeric Hermitian checks use the inclusive tolerance `1e-10`.
3. If any coefficient fails, the whole inequality is entry-wise and construction emits one `pdlmi:ElementwiseInequality` warning. A relation never mixes semidefinite and entry-wise coefficient groups.

Direct semidefinite assembly stores one matrix-sign condition per cell, rate row, and local coefficient. Direct entry-wise assembly vectorizes each coefficient in MATLAB column-major order and stores one vector inequality for the complete entry family at that coefficient.

Pólya preserves the global mode after exact degree elevation. Putinar and Full Box give every column-major scalar entry its own independent scalar Gram certificate. Gram variables remain independent across entries, cells, and rate rows.

```matlab
yalmip('clear')
V = pdvar(3, 2, {[0 1]}, "full");
warning("off", "pdlmi:ElementwiseInequality")
C = V >= 0;
numel(C.Constraints)   % 2 coefficient groups; each contains 6 scalar entries
```

## <span id="pdvar-comparison-eq"></span>Equality: `eq`/`==`

Equality is direct coefficient equality by definition. It accepts rectangular and non-Hermitian residuals, vectorizes each coefficient in column-major order, and emits no inequality warning.

Ordinary value rows may equal ordinary value rows, and derivative-row objects
may equal derivative-row objects. `pdvar:InvalidEqualityRows` is reserved for
an ordinary operand compared with a derivative operand, or for an operand that
itself mixes ordinary and derivative row kinds across physical cells. Once
both operands are derivative-row objects, incompatible grids, `RateBounds`,
or matrix shapes remain subtraction-owned failures such as `pdvar:MixedGrid`
or `pdvar:InvalidSubtraction`.

```matlab
yalmip('clear')
V = pdvar(3, 2, {[0 1]}, "full");
Q = sdpvar(3, 2, "full");
C = V == Q;
identity = V == V;
identity.toYalmip()    % []
```

Proven numeric-zero identities are omitted, so `V == V` has empty `Constraints` and `toYalmip` returns `[]`. Equality is direct-only: constructor certificate options and `applyPolya`, `applyPutinar`, or `applyFullBoxPreorder` raise `pdlmi:UnsupportedEqualityCertificate` before validating an order.

Use `==` to construct modeling equalities. Use [`isequal`](/PD-LMI-package/documents/reference/pdvar/indexing-and-inspection/#pdvar-isequal) only for MATLAB structural comparison of package objects.

## Returned object and properties

All three operators return `pdlmi`. Inspect the result with dot access:

```matlab
C.Relation
C.Residual
C.Constraints
```

`Relation` is `"<="`, `">="`, or `"=="`; `Residual` is the promoted `lhs-rhs`; `Constraints` is the already assembled finite cell array.

## Validation and errors

- Incompatible operand promotion raises the owning `pdvar` grid, degree, matrix-size, or rate-row error.
- Entry-wise inequality fallback is supported behavior and warns once with `pdlmi:ElementwiseInequality`; it is not an invalid-matrix error.
- Ordinary-versus-derivative operands, or one operand mixing row kinds across cells, raise `pdvar:InvalidEqualityRows`.
- When both operands are derivative-row objects, incompatible grids, `RateBounds`, or shapes retain subtraction-owned errors such as `pdvar:MixedGrid` or `pdvar:InvalidSubtraction`.
- Equality certificate selection raises `pdlmi:UnsupportedEqualityCertificate`.
- No comparison adds strictness, a positivity margin, or a solver call.
