## Purpose

Return a discontinuous, rate-vertex derivative expression for a `pdvar` object.

## Syntax

```matlab
D = rhodiff(P, rb)
D = rhodiff(P)
```

## Arguments

| Argument | Description |
| :--- | :--- |
| `P` | A `pdvar` expression that is not already a rate-vertex derivative expression. |
| `rb` | Finite $\ell\times2$ rate-bound table, such as `[-1 1]` or `[-1 2; -3 5]`. Required unless `P` already carries matching `RateBounds`. |

## Output

`D` is a `pdvar` with `IsContinuous=false`, `NumRateRows` equal to the exact
stored-row count, and `SourceSummary="derivative"`. It inherits the usual read-only fields
(`GridInfo`, `MatrixSize`, `Degree`, `LocalValues`, `ContainsDecision`,
`RateBounds`, and the rest) and is inspected with ordinary dot syntax or
`coeffs`.

Each physical cell stores one coefficient row per distinct `rho_dot` vertex.
An axis contributes two choices only when its lower and upper bounds differ.
Thus `NumRateRows` equals the product of the per-axis distinct-choice counts,
and it is $2^\ell$ only when every axis varies. The coefficient columns still
follow the Bernstein label order returned by `D.lbls()`.

The forward differences stay inside physical cell $c$. Rate rows are neither
new cells nor new local Bernstein labels; they enumerate the vertices needed
because the derivative expression is affine in $\dot{\boldsymbol\rho}$.
For several parameters, the partial along each nonconstant axis is elevated
exactly to `P.Degree` before the rate-weighted rows are added. A zero-degree
axis contributes the zero partial. Consequently, multivariate `rhodiff`
preserves the common direction-wise degree row.

<Aside type="note" title="Implementation remark: common-basis rate rows">
Within each physical cell, `rhodiff` forms forward differences along every
nonconstant parameter axis and scales them by degree over cell width. It
elevates the directional partials independently to one common tensor degree,
then weights and sums them for the deterministic `helper.combRows` ordering of
rate-box vertices. Each vertex remains a separate stored row.
</Aside>

## Example

```matlab
yalmip('clear')
P = pdvar(1, {[0 1 2]}, RateBounds=[-1 1]);
D = rhodiff(P);
D.Degree
D.IsContinuous
D.NumRateRows
D.RateBounds
size(D.coeffs(1))
```

```text
ans =
     0

ans =
  logical
   0

ans =
     2

ans =
    -1     1

ans =
     2     1
```

The `2 x 1` coefficient table has two rate rows because the scalar rate box
has two vertices, `-1` and `1`; it has one coefficient column because scalar
degree-1 derivatives become degree-0 coefficient rows.

For multiple parameters, the rate vertices are ordered as the same
lower/upper Cartesian-product order used by `helper.combRows`. For example,
`rb = [-1 2; -3 5]` gives four rows:

```text
(-1, -3)
(-1,  5)
( 2, -3)
( 2,  5)
```

Three parameters give `2^3 = 8` rows:

```matlab
yalmip('clear')
rb = [-1 2; -3 5; 0 4];
P = pdvar(1, {[0 1], [0 1], [0 1]}, RateBounds=rb);
D = rhodiff(P);
size(D.coeffs([1 1 1]))
```

```text
ans =
     8     8
```

The first `8` is the number of rate vertices. The second `8` is
`prod(D.Degree+1)`; multivariate derivatives are elevated into a common tensor
degree basis before the rate-weighted sum is stored. This design keeps
derivative evidence cell-local and lets `pdlmi` later check affine
`rho_dot` dependence by finite rate-box vertices.

Fixed axes collapse before storage. For `rb = [1 1; -3 5]`, the first rate is
always `1`, the second rate has two endpoints, and `D.NumRateRows` is `2`.

## Validation And Errors

- `rhodiff(P)` without stored rate bounds raises `pdvar:MissingRateBounds`.
- Explicit bounds with the wrong shape or invalid lower/upper order raise `pdvar:InvalidRateBounds`.
- Explicit bounds that do not match existing object bounds raise `pdvar:RateBoundsMismatch`.
- Re-differentiating an existing rate-vertex expression raises `pdvar:InvalidDiff`.

- Products with rate dependence on both sides raise the documented product-validation error.
- A rate-dependent expression can multiply known data; multiplication by another decision expression is rejected to preserve affine YALMIP dependence.
