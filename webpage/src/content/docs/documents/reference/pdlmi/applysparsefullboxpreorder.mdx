# `applySparseFullBoxPreorder`

`applySparseFullBoxPreorder` rebuilds an inequality from its stored `Residual`
with the sparse full-box family. It retains every FullBox parity or
generator-mask term and every exact target-coefficient identity, while
replacing each dense Gram matrix $Q_J$ by a symmetric block-band Gram matrix
$Q_J^{(w)}$ of bandwidth $w$.

## Syntax

```matlab
Csparse = C.applySparseFullBoxPreorder()
Csparse = C.applySparseFullBoxPreorder(w)
Csparse = C.applySparseFullBoxPreorder(w, r)
Csparse = C.applySparseFullBoxPreorder(..., ValidationMode=mode)
```

The same family is available at construction:

```matlab
Csparse = pdlmi(expr, relation, "UseSparseFullBoxPreorder")
Csparse = pdlmi(expr, relation, UseSparseFullBoxPreorder=true)
Csparse = pdlmi(expr, relation, BandWidth=w)
Csparse = pdlmi(expr, relation, BandWidth=w, SparseFullBoxOrder=r)
```

## Arguments

| Argument | Contract |
| :--- | :--- |
| `C` | Any `pdlmi` object. The method always rebuilds from `C.Residual`; it does not add constraints to the currently selected family. |
| `w` | Finite positive integer bandwidth for the symmetric block-band Gram matrix $Q_J^{(w)}$. Default `2`. |
| `r` | Finite nonnegative integer scalar shorthand or an $\ell$-element direction-wise absolute Gram order. It is not an increment from the residual degree. |

For assembled residual degree `M`, the default and minimum admissible order are
`floor(M/2)` in one parameter and componentwise `ceil(M/2)` in two or more
parameters. Order validation occurs before endpoint normalization. The
accepted order is stored as a $1\times\ell$ row.

## Returned Object And Read-Only State

`Csparse` is a new value object; `C` is unchanged. At an intermediate width,
the returned state is:

```matlab
Csparse.UseSparseFullBoxPreorder
Csparse.SparseFullBoxOrder
Csparse.BandWidth
```

with values `true`, `r`, and `w`. The other certificate selectors are false.
These properties are read-only from user code.

The exact endpoints are canonical:

- `w == 1` returns an actual Direct object. Its sparse selector is false and
  its sparse order and width are zero.
- `w >= max(r + 1)` returns an actual FullBox object. Its sparse selector is false,
  and `UseFullBoxPreorder` and `FullBoxOrder` describe the selected family.
- `1 < w < max(r + 1)` returns a SparseFullBox object.

The endpoint states are intentionally normalized; callers should inspect the
returned object instead of inferring its family from the requested width.

## Certificate Construction

For selected absolute order $\mathbf r$, use the paper notation
$\mathbf a_J=\mathbf r-\boldsymbol\chi_J$. Define the generator weight and
lifted Bernstein basis by

$$
\begin{aligned}
g_J(\boldsymbol\alpha)
&:=\prod_{s\in J}g_s(\boldsymbol\alpha),\\
Z_J(\boldsymbol\alpha)
&:=\mathbf b_{\mathbf a_J}(\boldsymbol\alpha)\otimes I_n.
\end{aligned}
$$

The contribution for subset $J$ and the complete certificate are

$$
\begin{aligned}
T_J^{(w)}(\boldsymbol\alpha)
&:=g_J(\boldsymbol\alpha)\,
  Z_J(\boldsymbol\alpha)^{\mathsf T}\\
&\qquad{}\cdot Q_J^{(w)}Z_J(\boldsymbol\alpha),\\
Q_J^{(w)}&\succeq0,\\
S^{(\mathbf c)}(\boldsymbol\alpha)
&=\sum_{J\subseteq\{1,\ldots,\ell\}}
  T_J^{(w)}(\boldsymbol\alpha).
\end{aligned}
$$

Every $Q_J^{(w)}$ is symmetric block-band with bandwidth $w$; terms with a
negative component in $\mathbf a_J$ are omitted. The one-parameter
parity-specific formulas use the same replacement $Q_J\mapsto Q_J^{(w)}$.
Exact coefficient matching is unchanged.

Certificates are independent for every physical cell, every active rate row,
and every column-major matrix entry. A symmetric matrix inequality uses
matrix-valued PSD blocks. An elementwise inequality uses independent scalar
certificates for all entries. Cell-boundary residual handles may be shared,
but Gram variables are not.

## Deterministic Transcript

```matlab
yalmip('clear')
P = pdvar(1, {[0 1]}, "symmetric", Degree=4);
direct = P >= 0;

sparse = direct.applySparseFullBoxPreorder();

directEndpoint = direct.applySparseFullBoxPreorder(1, 2);
denseEndpoint = direct.applySparseFullBoxPreorder(3, 2);
```

For the scalar one-parameter degree-four fixture at order two and width two,
each $Q_J^{(2)}$ is block tridiagonal; one cell stores three PSD blocks of
dimension two and five coefficient identities. Width one stores five Direct
coefficient tests; width three
stores the two dense FullBox PSD blocks and five identities.

`ValidationMode` is transient, accepts case-insensitive `"fast"` or
`"strict"`, applies only to this rebuild, and is neither stored nor inherited.

## Validation And Errors

- A malformed width raises `pdlmi:InvalidBandWidth`.
- A malformed order raises `pdlmi:InvalidSparseFullBoxOrder`.
- An integer below the dimension-dependent minimum raises
  `pdlmi:SparseFullBoxOrderTooLow`, including when `w == 1`.
- `UseSparseFullBoxPreorder=false` with `BandWidth` or
  `SparseFullBoxOrder` raises `pdlmi:ConflictingSparseFullBoxOptions`.
- Duplicate or malformed name-value syntax raises `pdlmi:DuplicateOption` or
  `pdlmi:InvalidOptions`.
- Enabling SparseFullBox together with Pólya, Putinar, or FullBox raises
  `pdlmi:ConflictingRelaxations`.
- Every certificate option on relation `"=="` raises
  `pdlmi:UnsupportedEqualityCertificate`. Equality rejection occurs before
  method-argument validation.

## Limitations

SparseFullBox is a fixed-order sufficient certificate, not an automatic
order search, chordal decomposition, or residual diagnostic. Increasing the
width nests the supported Gram patterns, but a strict feasibility improvement
is not guaranteed. Putinar and SparseFullBox have no total conservatism
ordering. The method assembles constraints but does not select a solver or
add a feasibility margin.
