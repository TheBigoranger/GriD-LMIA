Throughout this reference,
$S^{(\vect c)}=-\mathcal F^{(\vect c)}$ and $\vect M$ is the assembled
residual degree. See the
[global notation](/GriD-LMIA/documents/math/notation/#residual-and-positive-target).

`pdlmi` stores finite certificates generated from `pdvar` residuals or
coefficient-backed `pdmat` inequalities. Inequalities use semidefinite meaning
only when every original
coefficient is square Hermitian. Otherwise the whole inequality is entry-wise.
Equality is direct coefficient equality and may be rectangular. Direct
coefficient assembly is the default. Pólya degree elevation, fixed-order
Putinar box assembly, tensor-window SparsePutinar assembly, tensor-window
SparseFullBox assembly, and fixed-order
FullBox Bernstein-Gram preordering are explicit alternatives.

The six paths begin with the same stored residual. **Direct** tests every
local coefficient and is the default. **Pólya** exactly elevates that residual
before repeating the direct test. In one parameter, **Putinar** and
**FullBox** dispatch to the same parity-specific Markov–Lukács form with
minimum order `floor(M1/2)` for $\vect M=(M_1)$. In two or more parameters, Putinar uses an
unweighted Gram term plus one generator-weighted term per axis at minimum
componentwise `ceil(Degree/2)`, while FullBox includes every generator-subset product.
**SparsePutinar** retains the Putinar parity or singleton-generator terms and
uses overlapping tensor windows over each Bernstein Gram basis. In one
parameter, `CliqueSize=1` normalizes to Direct. In higher dimensions it
remains SparsePutinar. A saturated size greater than one normalizes to dense
Putinar. **SparseFullBox** retains the FullBox parity/generator-mask terms and exact
coefficient identities while replacing each dense tensor basis by
overlapping tensor windows of side length $w$. Side length one
canonicalizes to Direct, and a side at least
  `max(order + 1)` canonicalizes to FullBox. Every Gram path matches exact
box-polynomial identities. The
[SOS certificate chapter](/GriD-LMIA/documents/math/sos-certificates/)
derives these ideas. The API pages below stay focused on callable syntax.

## Implemented Behavior

Documentation v1.4.0 describes `<=`, `>=`, and `==` for affine `pdvar`
residuals and `<=`/`>=` for coefficient-backed known `pdmat` residuals.
Inequalities select
one global semidefinite or entry-wise interpretation from all original
coefficients. Equality is always direct and supports rectangular or
non-Hermitian residuals. Direct
coefficient-wise assembly is the default. Pólya assembly performs exact degree
elevation before applying the coefficient test. Putinar, SparsePutinar, SparseFullBox, and
FullBox assembly create independent positive-semidefinite Gram blocks for
every physical cell, active rate row, and column-major matrix entry, together
with exact Bernstein coefficient identities.

In one parameter, Putinar and FullBox share the parity-specific
Markov–Lukács interval construction. For two or more parameters, Putinar uses
an unweighted Gram term plus one term for each axis generator
$\alpha_s(1-\alpha_s)$, while the full-box preordering uses every subset product of those
generators. Both select a fixed absolute order on each local hypercube.
For `pdvar`, `toYalmip` concatenates the resulting finite constraints for an
ordinary YALMIP solver call. Direct and Pólya known-data wrappers export one
stored scalar logical certificate. Known-data Gram families still return
YALMIP constraints and may introduce auxiliary Gram variables.

## Properties

The constructor exposes private-set, read-only properties through dot access:

| Property | Example | Meaning |
| :--- | :--- | :--- |
| `Constraints` | `C.Constraints` | Stored direct conditions, Gram-block conditions, and/or exact identities. May be empty for a proven equality. |
| `Residual` | `C.Residual` | Promoted `lhs-rhs` expression used to rebuild alternative inequality certificates. |
| `Relation` | `C.Relation` | `"<="`, `">="`, or `"=="`. |
| `UsePolya`, `PolyaDegree` | `C.UsePolya`, `C.PolyaDegree` | Pólya selector and degree increment. |
| `UsePutinar`, `PutinarOrder` | `C.UsePutinar`, `C.PutinarOrder` | Putinar selector and absolute order. |
| `UseSparsePutinar`, `SparsePutinarOrder`, `CliqueSize` | `C.UseSparsePutinar`, `C.SparsePutinarOrder`, `C.CliqueSize` | SparsePutinar selector, direction-wise absolute order, and scalar tensor-window side `b`. |
| `UseSparseFullBoxPreorder`, `SparseFullBoxOrder`, `BandWidth` | `C.UseSparseFullBoxPreorder`, `C.SparseFullBoxOrder`, `C.BandWidth` | SparseFullBox selector, direction-wise absolute order, and scalar tensor-window side `w`. Side one normalizes to Direct. A side at least `max(order + 1)` normalizes to FullBox. |
| `UseFullBoxPreorder`, `FullBoxOrder` | `C.UseFullBoxPreorder`, `C.FullBoxOrder` | Full-box selector and absolute order. |

Certificate selectors apply only to inequalities. Any selector on equality raises `pdlmi:UnsupportedEqualityCertificate`.

The [SOS certificate map](/GriD-LMIA/documents/math/sos-certificates/)
derives these coefficient and Gram constructions, including the
one-dimensional Markov–Lukács form and the tensor box generators used in
higher dimensions.
