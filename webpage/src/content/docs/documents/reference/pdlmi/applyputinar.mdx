## Purpose

Create a new `pdlmi` that represents the stored residual with the implemented
cell-local Putinar box Bernstein-Gram certificate.

## Syntax

```matlab
Cputinar = C.applyPutinar()
Cputinar = C.applyPutinar(order)
Cputinar = C.applyPutinar(..., ValidationMode=mode)
```

## Description

The no-argument form selects the smallest admissible absolute order

$$
\mathbf r=\begin{cases}
\left\lfloor M/2\right\rfloor,&\ell=1,\\
\left\lceil \mathbf M/2\right\rceil,&\ell\ge2,
\end{cases}
$$

where $\mathbf M$ is `C.Residual.Degree` and $\ell$ is the parameter count. The
explicit form selects `order`; it does
not add `order` to the residual degree. Both forms rebuild from `C.Residual`
and `C.Relation`, return a new value object, and leave `C` unchanged. Applying
Putinar after Pólya, FullBox, or an earlier Putinar order therefore replaces
that selection rather than compounding it.

For each physical cell and active rate row, `pdlmi` first sign-normalizes the
target: a `>=` residual is used directly and a `<=` residual is negated. In
one parameter, the method dispatches to the same parity-specific
Markov–Lukács form as `applyFullBoxPreorder`. For two or more parameters, it
represents the target as

$$
\begin{aligned}
g_s(\boldsymbol\alpha)
&:=\alpha_s(1-\alpha_s),\\
\mathcal M_s(\boldsymbol\alpha)
&:=g_s(\boldsymbol\alpha)S_s(\boldsymbol\alpha),\\
S^{(\mathbf c)}(\boldsymbol\alpha)
&=S_0(\boldsymbol\alpha)
+\sum_{s=1}^{\ell}\mathcal M_s(\boldsymbol\alpha).
\end{aligned}
$$

At order $\mathbf r$, $S_0$ uses a tensor Bernstein Gram basis of degree
$\mathbf r$. The multiplier $S_s$ uses degree
$\mathbf r-\mathbf e_s$; a block is omitted if that vector has a negative
component. Every present Gram matrix is constrained positive semidefinite.
The target is exactly elevated and matched coefficient by coefficient at
tensor degree $2\mathbf r$.

For an entry-wise inequality, each MATLAB column-major scalar entry receives
an independent scalar certificate. Each cell and rate row receives independent dense Gram blocks and independent
coefficient equalities. The method does not share Gram variables across cells,
insert a positivity margin, call `optimize`, or choose a solver.
Thus the method creates non-strict constraints; a theoretical
$S^{(\mathbf c)}\succ0$ condition requires an explicit $\varepsilon I$
margin in the residual.

## Arguments

| Input | Description |
| :--- | :--- |
| `C` | Any `pdlmi` object. Its stored `Residual` and `Relation` are the source for the rebuilt certificate. |
| `order` | Optional finite nonnegative integer scalar shorthand or an $\ell$-element direction-wise absolute Gram order. It must satisfy $r\ge\lfloor M/2\rfloor$ in one parameter or $\mathbf r\ge\lceil\mathbf M/2\rceil$ componentwise in two or more parameters. |

## Returned Object

`Cputinar` is a new `pdlmi` with `UsePolya=false`,
`UseFullBoxPreorder=false`, `UsePutinar=true`, and `PutinarOrder` equal to the
selected order. Within each cell and rate row, `Constraints` stores the PSD
Gram-block conditions before the exact coefficient identities.
`toYalmip(Cputinar)` concatenates those stored entries without changing them.

## Deterministic Transcript Example

```matlab
yalmip('clear')
P = pdvar(1, {[0 1]}, Degree=2);
direct = P >= 0;
putinarDefault = direct.applyPutinar();
putinarHigher = putinarDefault.applyPutinar(2);
polya = direct.applyPolya(1);
putinarFromPolya = polya.applyPutinar();
Fputinar = toYalmip(putinarDefault);

direct.UsePutinar
direct.PutinarOrder
numel(direct.Constraints)
putinarDefault.UsePutinar
putinarDefault.PutinarOrder
numel(putinarDefault.Constraints)
putinarHigher.PutinarOrder
numel(putinarHigher.Constraints)
putinarFromPolya.UsePolya
putinarFromPolya.UsePutinar
putinarFromPolya.PutinarOrder
length(Fputinar)
```

For the degree-two scalar residual, order one stores two PSD blocks followed
by three exact coefficient identities. Order two stores two PSD blocks
followed by five identities. Selecting Putinar from `polya` returns to the
stored degree-two residual; it does not use the already elevated constraints.

`ValidationMode` is transient, accepts case-insensitive `"fast"` or
`"strict"`, applies only to this rebuild, and is neither stored nor inherited.

## Validation And Errors

- A malformed `order` raises `pdlmi:InvalidPutinarOrder`.
- A valid integer below $\lfloor m/2\rfloor$ in one parameter or $\lceil m/2\rceil$ in two or more parameters raises `pdlmi:PutinarOrderTooLow`.
- Semidefinite and entry-wise inequalities retain their original global mode.
- Equality is direct-only; this method raises `pdlmi:UnsupportedEqualityCertificate` before validating `order`.
- Constructor selection errors are documented on the
  [`pdlmi constructor`](/GriD-LMIA/documents/reference/pdlmi/constructor/)
  page, including `pdlmi:InvalidUsePutinar`,
  `pdlmi:ConflictingPutinarOptions`, and `pdlmi:ConflictingRelaxations`.

In one parameter, this selector uses the parity-specific Markov–Lukács
interval certificate. In two or more parameters it implements only the
local-hypercube module generated by the separate factors
$\alpha_s(1-\alpha_s)$. It is not a general-domain or general-generator
Putinar interface, a full-space SOS representation, an automatic order search,
or a solver call. Failure at one order does not prove that the target is
negative somewhere.

For two or more parameters, the distinct
[`applyFullBoxPreorder`](/GriD-LMIA/documents/reference/pdlmi/applyfullboxpreorder/)
method includes every subset product of the same generators. The two selectors
share the one-parameter parity rule and default order.
