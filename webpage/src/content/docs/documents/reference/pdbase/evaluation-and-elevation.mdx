These public methods are implemented once by `pdbase` and inherited by
`pdmat` and `pdvar`. The common implementation preserves the dynamic class and
payload type, while each derived class retains its own known-data, symbolic,
and rate-row meaning.

## <span id="pdbase-evaluate"></span>`evaluate`

### Syntax

```matlab
valueAtPoint = evaluate(obj, point)
valueAtPoint = obj.evaluate(point)
```

`point` is a finite real vector with one coordinate per parameter, inside the
closed physical bounds. The method locates one physical cell, converts to
local coordinates, and evaluates the tensor Bernstein row.

At an interior grid node the cell on the right owns the evaluation. At the
last grid node, the final cell owns it. Numeric coefficients return a numeric
matrix; symbolic coefficients return an `sdpvar` expression. A derivative
leaf returns a `1 × 2^npar` cell array, one reconstructed payload per stored
rate row in `helper.combRows` order.

```matlab
obj = pdbase({[0 1 2]}, [1 1], 1, {{0, 2}, {20, 40}});
leftInterior = obj.evaluate(1)
rightInterior = obj.evaluate(1 + eps)
```

```text
leftInterior =
    20

rightInterior =
   20.0000
```

The example uses discontinuous backend evidence deliberately: the exact
interior point uses the second cell, demonstrating right-cell ownership.

Invalid point shape or values use `<dynamic-class>:InvalidPoint`; an
out-of-bounds point uses `<dynamic-class>:PointOutOfBounds`. Thus a `pdmat`
call reports a `pdmat:` identifier and a `pdvar` call reports a `pdvar:`
identifier.

## <span id="pdbase-elevVals"></span>`elevVals`

### Syntax

```matlab
values = elevVals(obj, degreeIncrement)
values = obj.elevVals(degreeIncrement)
```

`degreeIncrement` accepts one finite nonnegative integer scalar shorthand or an
`npar(obj)`-element vector. It is added componentwise to `obj.Degree`; a scalar
expands uniformly. The returned value is an elevated nested `LocalValues` tree,
not an object. Physical cells, numeric or symbolic payloads, and independent
rate-row order are preserved; `obj` is unchanged.

```matlab
A = pdmat({[0 1]}, {0, 1}, Degree=1);
values = A.elevVals(1);
sourceDegree = A.Degree
elevatedRow = [values{1}{:}]
```

```text
sourceDegree =
     1

elevatedRow =
         0    0.5000    1.0000
```

An invalid increment raises `pdbase:InvalidDegreeIncrement`. A function-only
`pdmat` has no stored Bernstein evidence and raises
`pdbase:MissingCoefficientEvidence`.

## <span id="pdbase-elevate"></span>`elevate`

### Syntax

```matlab
out = elevate(obj, degreeIncrement)
out = obj.elevate(degreeIncrement)
```

`elevate` returns a new object with componentwise
`Degree + degreeIncrement` and the
elevated coefficients. It preserves the exact dynamic class, parameter grid,
payload shape, source metadata, `pdmat.FunctionHandle`, YALMIP variables,
continuity metadata, rate bounds, and rate-row order. The source value remains
unchanged.

```matlab
A = pdmat({[0 1]}, {1, 3}, Degree=1);
B = A.elevate(2);
classes = [string(class(A)) string(class(B))]
degrees = [A.Degree B.Degree]
values = [A.evaluate(0.3) B.evaluate(0.3)]
```

```text
classes =
  1x2 string array
    "pdmat"    "pdmat"

degrees =
     1     3

values =
    1.6000    1.6000
```

Validation matches `elevVals`, including the function-only missing-evidence
boundary. Degree elevation changes the Bernstein representation, not the
represented polynomial, physical grid, or ownership of interior boundaries.

## <span id="pdbase-rhodiff"></span>`rhodiff`

```matlab
D = rhodiff(A)
D = rhodiff(A, rateBounds)
```

`rhodiff` differentiates coefficient-backed storage cell by cell and returns
the same dynamic class. Explicit bounds supply missing metadata but must match
stored bounds when both are present. One-parameter degree `m > 0` becomes
`m-1`, while degree zero stays zero. With several parameters, the partial along
axis `s` has degree `Degree-e_s` when `Degree(s)>0`, then is elevated exactly
to the common vector `Degree` before rate weighting. A zero-degree axis
contributes the zero partial. Every physical cell stores one row per rate-box
vertex in `helper.combRows` order.

```matlab
A = pdbase({[0 2]}, [1 1], 1, {{1, 5}}, ...
    RateBounds=[-2 3]);
D = rhodiff(A);
derivativeClass = class(D)
derivativeDegree = D.Degree
derivativeRows = cell2mat(D.coeffs(1))
```

```text
derivativeClass = 'pdbase'
derivativeDegree = 0
derivativeRows = 2×1 double
    -4
     6
```

Function-only storage raises `pdbase:FunctionOnlyDiff`; existing rate rows
raise `pdbase:InvalidDiff`. Missing, malformed, or inconsistent bounds raise
`pdbase:MissingRateBounds`, `pdbase:InvalidRateBounds`, or
`pdbase:RateBoundsMismatch`.
