Every operation acts on the matrix payload stored at each local Bernstein label. The returned `pdmat` preserves known-data semantics and exposes the aligned grid, degree, and payload shape through its properties.

## <span id="pdmat-plus"></span><span id="pdmat-minus"></span><span id="pdmat-uplus"></span><span id="pdmat-uminus"></span>Add, subtract, and align coefficients

```matlab
S = A + B; D = A - B; U = +A; N = -A;
```

`plus` and `minus` align compatible physical grids and exactly elevate the lower Bernstein degree before combining corresponding coefficients. Numeric constants are promoted to the payload size. `uplus` preserves the object; `uminus` negates every stored coefficient.

```matlab
A = pdmat({[0 1]}, {1, 2}, Degree=1);
B = pdmat({[0 1]}, {10, 20, 30}, Degree=2);
S = A + B; cS = S.coeffs(1);
Z = A - A; N = -A; U = +A;
fprintf('degree=%d\n', S.Degree); disp([cS{:}])
fprintf('minus=%g, uminus=%g, uplus=%g\n', ...
    Z.evaluate(0.5), N.evaluate(1), U.evaluate(0));
```

```text
degree=2
   11.0000   21.5000   32.0000
minus=0, uminus=-2, uplus=1
```

If compatible operands have different interior nodes, their sorted union is the common refinement. Grid refinement and degree elevation are independent alignment steps.

## <span id="pdmat-mtimes"></span>Multiply in Bernstein coefficient space

```matlab
K = A * B;
```

`mtimes` multiplies coefficient-backed functions exactly rather than at sample points. On one cell,

$$
R^{(c)}[\mathbf k]=
\sum_{\mathbf i+\mathbf j=\mathbf k}
\prod_{s=1}^{\ell}
\frac{\binom m{i_s}\binom n{j_s}}{\binom{m+n}{k_s}}
P^{(c)}[\mathbf i]Q^{(c)}[\mathbf j].
$$

Matrix order is preserved. Numeric scalars and matrices use the corresponding MATLAB-compatible left or right product. Degrees and tensor labels add componentwise.

## Validation and operation boundaries

- Function-only objects without Bernstein evidence are rejected by coefficient algebra.
- Physical bounds and matrix dimensions must be compatible before refinement or multiplication.
- `mtimes` is matrix multiplication; element-wise parameter-dependent products are not a public substitute.
- These methods return known `pdmat` data and do not introduce YALMIP decisions.
