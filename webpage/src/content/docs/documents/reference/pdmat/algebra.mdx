Every operation acts on the matrix payload stored at each local Bernstein label. The returned `pdmat` preserves known-data semantics and exposes the aligned grid, degree, and payload shape through its properties.

## <span id="pdmat-plus"></span><span id="pdmat-minus"></span><span id="pdmat-uplus"></span><span id="pdmat-uminus"></span>Add, subtract, and align coefficients

```matlab
S = A + B; D = A - B; U = +A; N = -A;
```

`plus` and `minus` align compatible physical grids and exactly elevate each
operand to the componentwise maximum of their direction-wise degrees before
combining corresponding coefficients. Numeric constants are promoted to the
payload size. `uplus` preserves the object; `uminus` negates every stored
coefficient.

<CallGraph family="alignment" caption="Binary algebra aligns grids, rate bounds, and every degree component before cell-row assembly." links={[

  { href: "#pdmat-plus", label: "plus and minus API" },
  { href: "/GriD-LMIA/documents/reference/pdvar/algebra/", label: "pdvar algebra" },

```matlab
A = pdmat({[0 1]}, {0, 2}, Degree=1);
B = pdmat({[0 1]}, {1, 3, 5}, Degree=2);
S = A + B;
disp(bernTable(S, 1, "oneLine"))
```

```text
    CellSubscript              Expression
    _____________    _______________________________

        {[1]}        "(1-α)^2*1 + 2(1-α)α*4 + α^2*7"
```

For example, elevating a degree-one row to degree two gives

$$
[a_0,a_1]
\longmapsto
\left[a_0,\frac{a_0+a_1}{2},a_1\right].
$$

<MatrixGlyphDiagram before={[["a₀", "½(a₀+a₁)", "a₁"], ["b₀", "b₁", "b₂"]]} after={[["a₀+b₀", "½(a₀+a₁)+b₁", "a₁+b₂"]]} beforeLabel="degree-elevated rows" afterLabel="coefficient sum" caption="Degree elevation changes the representation, not the polynomial; addition then combines aligned local labels." />

If compatible operands have different interior nodes, their sorted union is the common refinement. Grid refinement and degree elevation are independent alignment steps.

<Aside type="note" title="Implementation remark: exact addition alignment">
`plus` and `minus` first form the sorted-union refinement of compatible grid vectors and
exactly re-express both operands on that refinement. They then elevate every
direction to the componentwise maximum degree and apply addition or subtraction
coefficient by coefficient. Neither alignment stage samples the represented
function.
</Aside>

### Different grids and direction-wise degrees

The two alignment stages are visible together in this example. `A` is affine
only along the first parameter, while `B` is quadratic only along the second.
Their physical grids have different interior nodes on both axes.

```matlab
A = pdmat({[0 0.4 1], [0 1]}, @(r1,r2) r1, Degree=[1 0]);
B = pdmat({[0 0.7 1], [0 0.25 1]}, @(r1,r2) r2^2, Degree=[0 2]);
S = A + B;
S.GridInfo.Vectors{1}
S.GridInfo.Vectors{2}
disp(bernTable(S, [1 1], "oneLine"))
```

```text
ans =
         0    0.4000    0.7000    1.0000

ans =
         0    0.2500    1.0000

    CellSubscript                                                                 Expression
    _____________    _____________________________________________________________________________________________________________________________________

       {[1 1]}       "(1-α1) * (1-α2)^2*0 + (1-α1) * 2(1-α2)α2*0 + (1-α1) * α2^2*0.0625 + α1 * (1-α2)^2*0.4000 + α1 * 2(1-α2)α2*0.4000 + α1 * α2^2*0.4625"
```

The represented functions are re-expressed exactly on the sorted-union grid,
then elevated to the componentwise maximum degree `[1 2]`. No sampling or
approximate interpolation is used. See
[Gridding and local coordinates](/GriD-LMIA/documents/math/gridding-and-degree/)
for physical-cell refinement and
[`elevate`](/GriD-LMIA/documents/reference/pdmat/elevate/) for the
componentwise coefficient transform.

## <span id="pdmat-mtimes"></span>Multiply in Bernstein coefficient space

<CallGraph family="multiplication" caption="mtimes dispatches one of three ordered coefficient-product kernels after alignment." links={[
  { href: "/GriD-LMIA/documents/math/coordinates-and-bernstein/coefficient-algebra/#normalized-product-identity", label: "Product mathematics" },
  { href: "#pdmat-mtimes", label: "mtimes API" },
  { href: "/GriD-LMIA/documents/reference/pdvar/algebra/", label: "pdvar mtimes" },
]} />

```matlab
K = A * B;
```

`mtimes` multiplies coefficient-backed functions exactly rather than at sample points. On one cell,

$$
\omega_s(i_s,j_s)
:=\frac{\binom{m_s}{i_s}\binom{n_s}{j_s}}
{\binom{m_s+n_s}{i_s+j_s}},
$$

and let the tensor-product weight be

$$
\Omega(\mathbf i,\mathbf j)
:=\prod_{s=1}^{\ell}\omega_s(i_s,j_s).
$$

The ordered coefficient convolution is then

$$
\begin{aligned}
R^{(c)}[\mathbf k]
&=\sum_{\mathbf i+\mathbf j=\mathbf k}
  \Omega(\mathbf i,\mathbf j)\\
&\qquad{}\cdot
  P^{(c)}[\mathbf i]Q^{(c)}[\mathbf j].
\end{aligned}
$$

Matrix order is preserved. Numeric scalars and matrices use the corresponding MATLAB-compatible left or right product. Degrees and tensor labels add componentwise.

<Aside type="note" title="Implementation remark: ordered product convolution">
`mtimes` builds one normalized Bernstein product plan for the two
direction-wise degree rows. On each common-refinement cell it accumulates
left-label/right-label pairs in written matrix-factor order, and stores the
result at their summed tensor label. The output degree is the componentwise
sum, not a fitted degree inferred from samples.
</Aside>

The implementation visits contribution pairs in increasing left label, with
`j = k-i`, and keeps matrix multiplication in that order. A scalar
degree-one check makes the normalized middle coefficient explicit:

```matlab
A = pdmat({[0 1]}, {2, 4}, Degree=1);
B = pdmat({[0 1]}, {3, 5}, Degree=1);
K = A * B;
disp(bernTable(K, 1, "oneLine"))
```

```text
    CellSubscript               Expression
    _____________    _________________________________

        {[1]}        "(1-α)^2*6 + 2(1-α)α*11 + α^2*20"
```

Here the middle Bernstein coefficient is `11 = 0.5*(2*5 + 4*3)`; this is an ordered coefficient
convolution, not a pointwise product of sampled rows.

```matlab
grid = {[0 1], [10 20]};
A = pdmat(grid, {1 2; 3 4}, Degree=[1 1]);
B = pdmat(grid, {5 6; 7 8}, Degree=[1 1]);
K = A * B;
disp(bernTable(K, [1 1], "oneLine"))
```

```text
    CellSubscript                                                                                                     Expression
    _____________    ____________________________________________________________________________________________________________________________________________________________________________________________________________

       {[1 1]}       "(1-α1)^2 * (1-α2)^2*5 + (1-α1)^2 * 2(1-α2)α2*8 + (1-α1)^2 * α2^2*12 + 2(1-α1)α1 * (1-α2)^2*11 + 2(1-α1)α1 * 2(1-α2)α2*15 + 2(1-α1)α1 * α2^2*20 + α1^2 * (1-α2)^2*21 + α1^2 * 2(1-α2)α2*26 + α1^2 * α2^2*32"
```

The degrees need not match or be positive on every axis:

```matlab
A = pdmat({[0 1], [0 2]}, @(r1,r2) 1 + r1, Degree=[1 0]);
B = pdmat({[0 1], [0 2]}, @(r1,r2) 2 + r2^2, Degree=[0 2]);
K = A * B;
disp(bernTable(K, [1 1], "oneLine"))
```

```text
    CellSubscript                                                        Expression
    _____________    __________________________________________________________________________________________________________________

       {[1 1]}       "(1-α1) * (1-α2)^2*2 + (1-α1) * 2(1-α2)α2*2 + (1-α1) * α2^2*6 + α1 * (1-α2)^2*4 + α1 * 2(1-α2)α2*4 + α1 * α2^2*12"
```

The tensor convolution adds degrees componentwise, so `[1 0]+[0 2]=[1 2]`;
the zero-degree axes remain valid inputs rather than being promoted before
multiplication. The complete coefficient rule is derived in
[Coefficient algebra](/GriD-LMIA/documents/math/coordinates-and-bernstein/coefficient-algebra/).

## Validation and operation boundaries

- Function-only objects without Bernstein evidence are rejected by coefficient algebra.
- Physical bounds and matrix dimensions must be compatible before refinement or multiplication.
- `mtimes` is matrix multiplication; element-wise parameter-dependent products are not a public substitute.
- Ordinary one-row operands broadcast across explicit rate rows. Two
  rate-row operands must have exactly matching grids and nonempty matching
  rate boxes; they are not automatically refined.
- Multiplication preserves rate rows when only one side has them. Rate-row by
  rate-row products, rate-row by ordinary decision products, and
  metadata-only rate dependence in a product are rejected.
- These methods return known `pdmat` data and do not introduce YALMIP decisions.
