## Purpose

Evaluate a `pdmat` object at a finite parameter point.

## Syntax

```matlab
val = evaluate(A, pt)
val = A.evaluate(pt)
```

## Arguments

| Argument | Description |
| :--- | :--- |
| `A` | A `pdmat` object. |
| `pt` | Finite real scalar for one parameter, such as `0.25`, or a row vector with one entry per parameter, such as `[0.25 12]`. The point must lie inside the grid bounds. |

## Output

For ordinary data, `val` is a numeric matrix with size `A.MatrixSize`. For
explicit rate-row data, it is a `1 × A.NumRateRows` cell row containing one
numeric matrix per distinct stored rate vertex.

## Description

For coefficient-backed data, let the evaluation point lie in the physical cell

$$
\begin{aligned}
\mathcal H_{\boldsymbol c}
&:=\prod_{s=1}^{\ell}
\left[\rho_s^{(c_s)},\rho_s^{(c_s+1)}\right],\\
\boldsymbol\rho&\in\mathcal H_{\boldsymbol c},\\
\alpha_s
&:=\frac{\rho_s-\rho_s^{(c_s)}}
{\rho_s^{(c_s+1)}-\rho_s^{(c_s)}},\\
s&=1,\ldots,\ell.
\end{aligned}
$$

For direction-wise Bernstein degree
$\boldsymbol m=(m_1,\ldots,m_\ell)$, `evaluate` computes the tensor expansion

$$
\begin{aligned}
\mathcal I_{\boldsymbol m}
&:=\prod_{s=1}^{\ell}\{0,\ldots,m_s\},\\
A(\boldsymbol\rho)
&=A^{(\boldsymbol c)}(\boldsymbol\alpha),\\
A^{(\boldsymbol c)}(\boldsymbol\alpha)
&=\sum_{\boldsymbol i\in\mathcal I_{\boldsymbol m}}
C^{(\boldsymbol c)}[\boldsymbol i]\,
B_{\boldsymbol i}^{\boldsymbol m}(\boldsymbol\alpha).
\end{aligned}
$$

Here the tensor-product basis is

$$
\begin{aligned}
b_s(i_s,\alpha_s)
&:=\binom{m_s}{i_s}
\alpha_s^{i_s}(1-\alpha_s)^{m_s-i_s},\\
B_{\boldsymbol i}^{\boldsymbol m}(\boldsymbol\alpha)
&:=\prod_{s=1}^{\ell}b_s(i_s,\alpha_s).
\end{aligned}
$$

Each $C^{(\boldsymbol c)}[\boldsymbol i]$ is the stored scalar or matrix
coefficient at local label $\boldsymbol i$; the scalar basis weight multiplies
the entire coefficient matrix. Function-backed objects keep the exact MATLAB
function handle and call it directly.

<Aside type="note" title="Implementation remark: boundary ownership and row reconstruction">
At an interior grid node, `evaluate` selects the cell on the right; only the
global upper endpoint belongs to the final cell. It forms every tensor
Bernstein weight explicitly from the local coordinates and reconstructs each
stored ordinary or rate-vertex row independently in storage order. This path
does not use de Casteljau recursion or merge rate alternatives.
</Aside>

Explicit rate rows are interpolated independently; `evaluate` does not merge
the alternatives:

```matlab
A = pdmat([0 1], {{1, 3; 10, 14}}, ...
    Degree=1, RateBounds=[-1 2]);
rateRows = cell2mat(A.evaluate(0.5))
```

```text
rateRows = 1×2 double
     2    12
```

## Examples

### Function-call form

```matlab
A = pdmat({[0 1]}, {2, 4}, Degree=1);
val = evaluate(A, 0.25)
```

```text
val = 2.5000
```

At `rho = 0.25`, the public forward coordinate is `alpha = 0.25`, so the value is
`0.75*2 + 0.25*4`.

### Dot-call form

```matlab
A = pdmat({[0 1]}, {2, 4}, Degree=1);
val = A.evaluate(0.75)
```

```text
val = 3.5000
```

The dot-call form is equivalent to `evaluate(A, pt)` and is often convenient in
interactive MATLAB sessions.

### Function-backed evaluation

```matlab
F = pdmat({[0 pi]}, @(rho) sin(rho));
val = F.evaluate(pi/2)
```

```text
val = 1
```

Function-backed objects route evaluation through the retained function handle.

## Validation And Errors

- Bad point shape or nonfinite values raise `pdmat:InvalidPoint`.
- Points outside grid bounds raise `pdmat:PointOutOfBounds`.
- Function-handle failures during evaluation raise `pdmat:InvalidFunctionValue`.
