or the represented known-data function. The implementation is inherited from
`pdbase`; the returned object remains a `pdmat`.

## What degree elevation does

On physical cell $\mathcal H_{\boldsymbol c}$, write the
direction-wise-degree-$\boldsymbol m$ tensor
Bernstein coefficients as
$C^{(\boldsymbol c)}[\boldsymbol i]$,
$\boldsymbol i\in\prod_s\{0,\ldots,m_s\}$. Elevation to any
$\boldsymbol M\ge\boldsymbol m$ componentwise is defined directly by

<KaTeXMath
  class="formula-block formula-one-line"
  tex={String.raw`A^{(\boldsymbol c)}(\boldsymbol\alpha)=\sum_{\boldsymbol i\in\prod_s\{0,\ldots,m_s\}}C^{(\boldsymbol c)}[\boldsymbol i]B_{\boldsymbol i}^{\boldsymbol m}(\boldsymbol\alpha)=\sum_{\boldsymbol k\in\prod_s\{0,\ldots,M_s\}}\hat C^{(\boldsymbol c)}[\boldsymbol k]B_{\boldsymbol k}^{\boldsymbol M}(\boldsymbol\alpha).`}
/>

The elevated coefficients are

<div className="elevate-direct-coefficient-scroll">

<KaTeXMath
  class="formula-block formula-one-line"
  tex={String.raw`\hat C^{(\boldsymbol c)}[\boldsymbol k]=\sum_{\boldsymbol i\in\prod_s\{0,\ldots,m_s\}}\left[\prod_{s=1}^{\ell}\frac{\binom{m_s}{i_s}\binom{M_s-m_s}{k_s-i_s}}{\binom{M_s}{k_s}}\right]\cdot C^{(\boldsymbol c)}[\boldsymbol i],\qquad \boldsymbol k\in\prod_s\{0,\ldots,M_s\}.`}
/>

</div>

As usual, a binomial coefficient with an index outside its natural range is
zero. This direct sum is the mathematical coefficient rule: it gives every
elevated coefficient from the original coefficient tensor without introducing
an implementation-specific data layout.

<Aside type="note" title="Implementation remark: normalized convolution">

The package evaluates the same direct rule as a normalized tensor convolution.
Let $\boldsymbol d:=\boldsymbol M-\boldsymbol m$. Its direction-wise
degree-$\boldsymbol d$ elevation kernel is

<KaTeXMath
  class="formula-block formula-one-line"
  tex={String.raw`\mathcal E_{\boldsymbol d}[\boldsymbol j]:=\prod_{s=1}^{\ell}\binom{d_s}{j_s},\qquad\boldsymbol j\in\prod_s\{0,\ldots,d_s\}.`}
/>

The complete elevation is the normalized $\ell$-dimensional convolution
of the original coefficient tensor with that kernel:

<KaTeXMath
  class="formula-block formula-one-line"
  tex={String.raw`\left\{\left(\prod_{s=1}^{\ell}\binom{M_s}{k_s}\right)\hat C^{(\boldsymbol c)}[\boldsymbol k]\right\}_{\boldsymbol k}=\left\{\left(\prod_{s=1}^{\ell}\binom{m_s}{i_s}\right)C^{(\boldsymbol c)}[\boldsymbol i]\right\}_{\boldsymbol i}\ast_{\ell}\left\{\mathcal E_{\boldsymbol d}[\boldsymbol j]\right\}_{\boldsymbol j}.`}
/>

</Aside>

This unique degree-$\boldsymbol M$ coefficient tensor represents exactly the
same polynomial. A cell grows from $\prod_s(m_s+1)$ to
$\prod_s(M_s+1)$ local labels; only the representation changes.

Relative to the [`pdmat Storage` figure](/GriD-LMIA/documents/reference/pdmat/storage-and-elevation/),
`cells(A)`, the physical grid, and shared cell interfaces stay fixed.
Only the tensor lattice inside every `LocalValues` branch is replaced by a
larger exact representation: `ncell(A)` and `npar(A)` stay fixed, while
`ncoeff(A)` increases.

<Aside type="note" title="Implementation remark: copy, do not reconstruct">

The inherited value-class implementation first computes the elevated tree,
then assigns `out = obj` and updates only `out.Degree` and
`out.LocalValues`. Copying the existing dynamic object preserves its concrete
class, physical grid, matrix and continuity metadata, `SourceSummary`,
`FunctionHandle`, rate-row ordering, and any YALMIP variables already stored
in subclass state. Elevation therefore replaces coefficient evidence without
reconstructing either a `pdmat` or a `pdvar`.

</Aside>

Degree elevation is therefore useful when two Bernstein operands need a common
degree or when a finite certificate requests additional coefficient evidence.
It is not grid refinement, interpolation, or an approximation step.

## <span id="pdmat-elevate"></span>`elevate`

```matlab
B = elevate(A,degreeIncrement)
B = A.elevate(degreeIncrement)
```

Returns a `pdmat` with the same grid, matrix shape, continuity metadata,
`SourceSummary`, and `FunctionHandle`, but with elevated degree and coefficient
evidence. It packages the elevated `LocalValues` described above into a new
object; evaluation is exactly preserved.

### One-dimensional coefficient rule and example

For one coordinate and one elevation step, the tensor convolution reduces to
the familiar recurrence

<KaTeXMath
  class="formula-block formula-one-line"
  tex={String.raw`\mathbf m=(m_1),\qquad\tilde a_0=a_0,\qquad\tilde a_{m_1+1}=a_{m_1},\qquad\tilde a_{i_1}=\frac{i_1}{m_1+1}a_{i_1-1}+\left(1-\frac{i_1}{m_1+1}\right)a_{i_1},\quad 1\le i_1\le m_1.`}
/>

The following degree $\mathbf m=(1)$ row $[0,2]$ is elevated by
$\mathbf d=(3)$ to degree $(4)$. The direct selected-cell output shows the
complete elevated representation.

```matlab
A = pdmat({[0 1]}, {0, 2}, Degree=1);
B = A.elevate(3);
disp(bernTable(B, 1, "oneLine"))
```

```text
    CellSubscript                                   Expression
    _____________    _________________________________________________________________________

        {[1]}        "(1-α)^4*0 + 4(1-α)^3α*0.5000 + 6(1-α)^2α^2*1 + 4(1-α)α^3*1.5000 + α^4*2"
```

### Direction-wise elevation with a zero-degree axis

An increment is applied componentwise. This example starts from
`Degree=[1 0]`, so the second parameter is present in the tensor grid but the
represented function is constant along that axis. Elevating by `[1 2]`
produces `Degree=[2 2]` and nine local tensor-product labels per cell without
changing any evaluated value.

```matlab
A2 = pdmat({[0 1], [0 2]}, @(r1,r2) 1 + r1, Degree=[1 0]);
B2 = A2.elevate([1 2]);
disp(bernTable(B2, [1 1], "oneLine"))
```

```text
    CellSubscript                                                                                                         Expression
    _____________    ____________________________________________________________________________________________________________________________________________________________________________________________________________________

       {[1 1]}       "(1-α1)^2 * (1-α2)^2*1 + (1-α1)^2 * 2(1-α2)α2*1 + (1-α1)^2 * α2^2*1 + 2(1-α1)α1 * (1-α2)^2*1.5000 + 2(1-α1)α1 * 2(1-α2)α2*1.5000 + 2(1-α1)α1 * α2^2*1.5000 + α1^2 * (1-α2)^2*2 + α1^2 * 2(1-α2)α2*2 + α1^2 * α2^2*2"
```

An invalid increment raises `pdbase:InvalidDegreeIncrement`. A function-only
object constructed without explicit `Degree` raises
`pdbase:MissingCoefficientEvidence` for both elevation methods. Elevation is
representation-only: it does not refine the physical grid or sample a
function-only source.
