Degree elevation changes the Bernstein representation, not the physical grid
or the represented known-data function. The implementation is inherited from
`pdbase`; the returned object remains a `pdmat`.

## What degree elevation does

On physical cell $\mathcal H_{\boldsymbol c}$, write the
direction-wise-degree-$\boldsymbol m$ tensor
Bernstein coefficients as
$C^{(\boldsymbol c)}[\boldsymbol i]$,
$\boldsymbol i\in\prod_s\{0,\ldots,m_s\}$. Elevation to any
$\boldsymbol M\ge\boldsymbol m$ componentwise is defined directly by

$$
\begin{aligned}
A^{(\boldsymbol c)}(\boldsymbol\alpha)
&=\sum_{\boldsymbol i\in\prod_s\{0,\ldots,m_s\}}
C^{(\boldsymbol c)}[\boldsymbol i]
B_{\boldsymbol i}^{\boldsymbol m}(\boldsymbol\alpha)\\
&=\sum_{\boldsymbol k\in\prod_s\{0,\ldots,M_s\}}
\widehat C^{(\boldsymbol c)}[\boldsymbol k]
B_{\boldsymbol k}^{\boldsymbol M}(\boldsymbol\alpha).
\end{aligned}
$$

The elevated coefficients are

$$
\begin{aligned}
\widehat C^{(\boldsymbol c)}[\boldsymbol k]
&=
\sum_{\boldsymbol i\in\prod_s\{0,\ldots,m_s\}}
\left[
\prod_{s=1}^{\ell}
\frac{
  \binom{m_s}{i_s}\binom{M_s-m_s}{k_s-i_s}
}{
  \binom{M_s}{k_s}
}
\right]\\
&\qquad{}\cdot C^{(\boldsymbol c)}[\boldsymbol i],\\
\boldsymbol k
&\in\prod_s\{0,\ldots,M_s\}.
\end{aligned}
$$

As usual, a binomial coefficient with an index outside its natural range is
zero. The direction-wise degree-$(\boldsymbol M-\boldsymbol m)$ elevation
kernel is

$$
\mathcal E_{\boldsymbol M-\boldsymbol m}[\boldsymbol j]
:=
\prod_{s=1}^{\ell}
\binom{M_s-m_s}{j_s},
\qquad
\boldsymbol j\in\prod_s\{0,\ldots,M_s-m_s\}.
$$

The complete elevation is the normalized $\ell$-dimensional convolution
written directly in the original and elevated coefficients:

$$
\begin{aligned}
\left\{
  \prod_{s=1}^{\ell}\binom{M_s}{k_s}
  \widehat C^{(\boldsymbol c)}[\boldsymbol k]
\right\}_{\boldsymbol k}
&=
\left\{
  \prod_{s=1}^{\ell}\binom{m_s}{i_s}
  C^{(\boldsymbol c)}[\boldsymbol i]
\right\}_{\boldsymbol i}
\\
&\qquad{}\ast_{\ell}
\left\{
  \mathcal E_{\boldsymbol M-\boldsymbol m}[\boldsymbol j]
\right\}_{\boldsymbol j}.
\end{aligned}
$$

This unique degree-$\boldsymbol M$ coefficient tensor represents exactly the
same polynomial. A cell grows from $\prod_s(m_s+1)$ to
$\prod_s(M_s+1)$ local labels; only the representation changes.

Relative to the [`pdmat Storage` figure](/PD-LMI-package/documents/reference/pdmat/storage-and-elevation/),
`cells(A)`, the physical grid, and shared cell interfaces stay fixed.
Only the tensor lattice inside every `LocalValues` branch is replaced by a
larger exact representation: `ncell(A)` and `npar(A)` stay fixed, while
`ncoeff(A)` increases.

Degree elevation is therefore useful when two Bernstein operands need a common
degree or when a finite certificate requests additional coefficient evidence.
It is not grid refinement, interpolation, or an approximation step.

## <span id="pdmat-elevVals"></span>`elevVals`

```matlab
elevatedTree = elevVals(A,degreeIncrement)
```

Returns numeric `LocalValues` elevated by a finite nonnegative integer scalar
shorthand or an `npar(A)`-element vector. The increment is added
componentwise; a scalar expands uniformly. In the Storage figure, this is the
larger tensor lattice inside each existing cell branch. `A` remains unchanged.

## <span id="pdmat-elevate"></span>`elevate`

```matlab
B = elevate(A,degreeIncrement)
B = A.elevate(degreeIncrement)
```

Returns a `pdmat` with the same grid, matrix shape, continuity metadata,
`SourceSummary`, and `FunctionHandle`, but with elevated degree and coefficient
evidence. It packages the elevated `LocalValues` described above into a new
object; evaluation is exactly preserved.

### One-dimensional coefficient rule and example

For one coordinate and one elevation step, the tensor convolution reduces to
the familiar recurrence

$$
\begin{aligned}
\widetilde a_0&=a_0,\\
\widetilde a_{m+1}&=a_m,\\
\widetilde a_i
&=\frac{i}{m+1}a_{i-1}
+\left(1-\frac{i}{m+1}\right)a_i,
\qquad 1\le i\le m.
\end{aligned}
$$

The following degree-one row $[1,3]$ is elevated twice to the degree-three row
$[1,\frac53,\frac73,3]$ without changing $A(\rho)=1+2\rho$.

```matlab
A = pdmat({[0 1]}, @(rho) 1 + 2*rho, Degree=1);
B = A.elevate(2);
classes = [string(class(A)) string(class(B))]
degrees = [A.Degree B.Degree]
sameValue = [A.evaluate(0.4) B.evaluate(0.4)]
sourceUnchanged = A.Degree
```

```text
classes =
  1x2 string array
    "pdmat"    "pdmat"

degrees =
     1     3

sameValue =
    1.8000    1.8000

sourceUnchanged =
     1
```

### Direction-wise elevation with a zero-degree axis

An increment is applied componentwise. This example starts from
`Degree=[1 0]`, so the second parameter is present in the tensor grid but the
represented function is constant along that axis. Elevating by `[1 2]`
produces `Degree=[2 2]` and nine local tensor-product labels per cell without
changing any evaluated value.

```matlab
A2 = pdmat({[0 1], [0 2]}, @(r1,r2) 1 + r1, Degree=[1 0]);
B2 = A2.elevate([1 2]);
B2.Degree
B2.ncoeff()
[A2.evaluate([0.25 1.5]) B2.evaluate([0.25 1.5])]
```

```text
ans =
     2     2

ans =
     9

ans =
    1.2500    1.2500
```

An invalid increment raises `pdbase:InvalidDegreeIncrement`. A function-only
object constructed without explicit `Degree` raises
`pdbase:MissingCoefficientEvidence` for both elevation methods. Elevation is
representation-only: it does not refine the physical grid or sample a
function-only source.
