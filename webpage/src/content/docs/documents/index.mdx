## Learn

Begin with the [notation dictionary](/GriD-LMIA/documents/math/notation/), then
follow modeling, tensor grids, Bernstein coordinates and algebra, rate
vertices, and finite certificates. Each guide defines its prerequisites and
connects the mathematics to a verified package operation.

The package represents continuous piecewise-polynomial matrix functions on
physical grid cells in a cell-local tensor-product Bernstein basis. `pdvar`
shares complete face values between adjacent cells. Differentiation remains
cell-local, which gives a continuous piecewise-polynomial representation with
cellwise derivatives. A DPD-LMI contains explicit derivative and rate terms.

## Documentation v1.3.2 Supported Scope

Version 1.3.2 documents the implemented package workflow after shared matrix
protocols, unary transformations, and reductions were centralized in
`pdbase`. The inherited operations remain complete public `pdmat` and `pdvar`
interfaces, with class-specific examples and validation. The supported
surface also includes function-backed and coefficient-backed `pdmat` known
data, degree-zero or continuous arbitrary-degree `pdvar` decisions,
discontinuous rate-vertex data produced by `rhodiff`, Direct `pdlmi`
constraints, opt-in Pólya degree increments, and fixed-order Putinar,
SparsePutinar, SparseFullBox, and FullBox Bernstein–Gram certificates. The
public surface also includes thirteen shared `+helper` functions.

The supported domain uses tensor-product box grids and affine decision
expressions. Products accept decision dependence on one side. Equality assembly
uses direct coefficient identities. A failed finite certificate remains
inconclusive for the original continuum inequality. Every requested positivity
margin appears explicitly in the model. YALMIP owns objectives, solver choice,
optimization, and diagnostics. General-domain and general-generator SOS
hierarchies provide mathematical context beyond the implemented API.

Start with [Install And Download](/GriD-LMIA/install/), verify the checkout with
`tests.run_all()`, and use the generated lookup for accepted forms, returned
shapes, validation rules, and supported scope across all 192 indexed records.
