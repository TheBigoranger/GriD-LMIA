The software state is `Putinar`. In one parameter its implementation uses the
parity-specific Markov–Lukács interval form; Markov–Lukács is not a separate
selector. The Gram notation below uses
$Z_a=\mathbf b_a\otimes I_n$ for matrix size $n$, where $\mathbf b_a$ is the
degree-$a$ Bernstein basis vector and every Gram matrix $Q$ satisfies
$Q\succeq0$.

## One-Parameter Even Degree

For assembled degree $M=2r$, represent the target as

$$
S^{(\mathbf c)}(\alpha)
=-\mathcal F^{(\mathbf c)}(\alpha)
=Z_r(\alpha)^{\mathsf T}Q_0Z_r(\alpha)
+\alpha(1-\alpha)
Z_{r-1}(\alpha)^{\mathsf T}Q_1Z_{r-1}(\alpha),
$$

with $Q_0,Q_1\succeq0$. The basis-to-coefficient Gram map is affine, and
every resulting Bernstein coefficient is matched exactly to
$C^{(\mathbf c)}[i]$.

## One-Parameter Odd Degree

For $M=2r+1$, use endpoint weights:

$$
S^{(\mathbf c)}(\alpha)
=(1-\alpha)Z_r^{\mathsf T}Q_0Z_r
+\alpha Z_r^{\mathsf T}Q_1Z_r,
\qquad Q_0,Q_1\succeq0.
$$

The minimum absolute order is $r=\lfloor M/2\rfloor$ in one parameter.

## Multivariate Putinar Module

For $\ell\ge2$, define
$g_s(\boldsymbol\alpha)=\alpha_s(1-\alpha_s)$. The implemented module is

$$
S^{(\mathbf c)}
=S_0+\sum_{s=1}^{\ell}g_sS_s,
$$

where each $S_s$ has a free positive-semidefinite Gram representation and the
sum matches every target coefficient exactly. The minimum absolute order is
$r=\lceil M/2\rceil$.

```matlab
selected = L.applyPutinar();
selected = L.applyPutinar(r);
constraints = selected.toYalmip();
```

Each cell, stored rate row, and column-major matrix entry receives independent
Gram blocks.
These are non-strict software constraints. The theoretical
$S^{(\mathbf c)}\succ0$ condition requires an explicit
$S^{(\mathbf c)}-\varepsilon I\succeq0$ margin in the modeled residual.

## Relation To FullBox

In one parameter, Putinar and FullBox use the same Markov–Lukács interval
form. In several parameters, Putinar includes only the unweighted and singleton
generator terms. FullBox includes every generator-subset product.

## Failure Interpretation

A fixed-order Gram model is a sufficient certificate. Failure may reflect
certificate order, numerical conditioning, memory pressure, grid choice, or
decision degree. It does not prove that $S$ becomes indefinite somewhere.

## Limitations

The implementation is specialized to box generators and fixed absolute order.
It is not a general semialgebraic-domain parser and does not choose an order or
solver automatically. Large Gram programs can be memory- or numerically
limited.
