# SparsePutinar Tensor Windows

SparsePutinar starts from the same local positive target $S^{(\vect c)}(\vect\alpha)$ as dense Putinar. It keeps the Putinar generator family and exact coefficient identities, but it replaces each dense Bernstein Gram basis by overlapping tensor windows. We first define the SOS and Gram objects, then give the dense Putinar form, the window decomposition, and the resulting dimension tradeoff.

## Scalar And Matrix SOS

A scalar polynomial $s(\vect\alpha)$ is a sum of squares when there are polynomial functions $h_1,\ldots,h_N$ such that

$$
s(\vect\alpha)=\sum_{j=1}^{N} h_j(\vect\alpha)^2.
$$

A symmetric polynomial matrix $S(\vect\alpha)$ is a matrix SOS when there is a polynomial matrix $H(\vect\alpha)$ such that $S=H^\top H$. Both definitions admit a Gram representation. Let $\vect b_{\vect d}$ contain the tensor Bernstein basis functions with labels $\vect i\in\prod_{s=1}^{\ell}\{0,\ldots,d_s\}$, and define $Z_{\vect d}=\vect b_{\vect d}\otimes I_n$. Then

$$
S(\vect\alpha)=Z_{\vect d}(\vect\alpha)^\top QZ_{\vect d}(\vect\alpha),
\qquad Q\succeq0.
$$

The PSD condition makes the represented matrix positive semidefinite at every $\vect\alpha$. However, the representation equals the target only after coefficient matching. The assembler therefore converts the Gram expression to the normalized Bernstein basis and equates every resulting coefficient matrix with the corresponding target coefficient.

## Dense Putinar Terms

In one parameter, the package keeps the parity-specific Markov–Lukács form.
Write $\vect M=(M_1)$ and $\vect r=(r_1)$. For
$M_1=2r_1$, define the two Gram terms

$$
\begin{aligned}
G_0(\alpha)&=Z_{\vect r}(\alpha)^\top Q_0Z_{\vect r}(\alpha),\\
G_1(\alpha)&=Z_{\vect r-\vect e_1}(\alpha)^\top Q_1Z_{\vect r-\vect e_1}(\alpha).
\end{aligned}
$$

Here, $Q_0\succeq0$ and $Q_1\succeq0$. The even-degree representation is

$$
S(\alpha)=G_0(\alpha)+\alpha(1-\alpha)G_1(\alpha).
$$

For target component $M_1=2r_1+1$, define the two Gram terms

$$
H_0(\alpha)=Z_{\vect r}(\alpha)^\top Q_0Z_{\vect r}(\alpha).
$$

Here, $Q_0\succeq0$.

$$
H_1(\alpha)=Z_{\vect r}(\alpha)^\top Q_1Z_{\vect r}(\alpha).
$$

Here, $Q_1\succeq0$.

The odd-degree representation is

$$
S(\alpha)=(1-\alpha)H_0(\alpha)+\alpha H_1(\alpha).
$$

In two or more parameters, define $g_0=1$ and $g_s=\alpha_s(1-\alpha_s)$ for $s=1,\ldots,\ell$. Let $\mathcal Q_{\mathrm P}\subseteq\{0,1,\ldots,\ell\}$ index the empty and singleton Putinar specifications whose Gram degrees are nonnegative. For each active specification, suppress the common argument $\vect\alpha$ and define the dense Gram term by

$$
D_q=Z_{\vect d_q}^\top Q_qZ_{\vect d_q},
$$

where $Q_q\succeq0$. Putinar uses only these active terms, so

$$
S^{(\vect c)}=\sum_{q\in\mathcal Q_{\mathrm P}}g_qD_q.
$$

Here, $\vect d_0=\vect r$ and $\vect d_s=\vect r-\vect e_s$. Terms with a negative degree component are omitted. This singleton family distinguishes Putinar from FullBox, which includes every square-free product of the axis generators.

## Tensor-Window Label Sets

Fix one active Gram specification with degree vector $\vect d$. For the
implemented `CliqueSize` value $b$, the window side on axis $s$ is

$$
w_s=\min(b,d_s+1).
$$

The start index satisfies $u_s\in\{0,\ldots,d_s-w_s+1\}$. For $\vect u=(u_1,\ldots,u_\ell)$, define the label set on axis $s$ by

$$
\mathcal W_s=\{u_s,\ldots,u_s+w_s-1\}.
$$

The tensor-window label set is the Cartesian product

$$
\mathcal W(\vect d,\vect u,b)=\prod_{s=1}^{\ell}\mathcal W_s.
$$

For the multidimensional empty and singleton family, let $\vect b_{\vect d,\vect u}$ contain only the Bernstein basis functions whose labels lie in $\mathcal W(\vect d,\vect u,b)$, and define $Z_{q,\vect u}=\vect b_{\vect d_q,\vect u}\otimes I_n$. SparsePutinar replaces the dense block $Q_q$ by one independent PSD block $Q_{q,\vect u}$ for each start vector. Suppressing the common argument $\vect\alpha$, define the contribution from one window by

$$
T_{q,\vect u}
=Z_{q,\vect u}^\top Q_{q,\vect u}Z_{q,\vect u},
$$

where $Q_{q,\vect u}\succeq0$. Accumulating all windows for one active specification gives

$$
T_q=\sum_{\vect u}T_{q,\vect u}.
$$

The complete representation is therefore

$$
S^{(\vect c)}=\sum_{q\in\mathcal Q_{\mathrm P}}g_qT_q.
$$

In one parameter, the package applies the same tensor-window split to the two
Markov–Lukács parity blocks shown above. Their weights are $1$ and
$\alpha(1-\alpha)$ for even target degree, or $1-\alpha$ and $\alpha$ for odd
target degree. The one-dimensional odd form therefore uses its parity-specific
generator in place of the multidimensional $g_q$ definition.

## Overlapping Coefficient Accumulation

Windows overlap, so one target Bernstein coefficient may receive contributions from several blocks. For the displayed multidimensional empty and singleton family, let $\mathcal A_{q,\vect u}(Q_{q,\vect u})[\vect k]$ denote the normalized Bernstein coefficient at target label $\vect k$ contributed by one weighted window, and write this quantity as $a_{q,\vect u}[\vect k]$. First accumulate all windows for one active specification:

$$
a_q[\vect k]=\sum_{\vect u}a_{q,\vect u}[\vect k].
$$

The exact accumulated equality is then

$$
C^{(\vect c)}[\vect k]
=\sum_{q\in\mathcal Q_{\mathrm P}}a_q[\vect k].
$$

This equality holds for every $\vect k\in\prod_{s=1}^{\ell}\{0,\ldots,M_s\}$.

This accumulated equality combines every window contribution. Therefore, each certificate copy keeps exactly

$$
\prod_{s=1}^{\ell}(M_s+1)
$$

target coefficient identities.

In one parameter, the assembler performs the identical accumulation over the two active Markov–Lukács parity blocks and all of their windows.

<Aside type="note" title="Implementation remark: independent copies">
The package builds a separate window family for every physical cell and stored rate row. Symmetric inequalities use matrix-valued Gram blocks, while an entrywise inequality creates a scalar certificate for each matrix entry in MATLAB column-major order.
</Aside>

## Block Dimensions And Counts

For a symmetric $n\times n$ target, one window block has dimension

$$
n\prod_{s=1}^{\ell}\min(b,d_s+1).
$$

The number of windows for that Gram specification is

$$
\prod_{s=1}^{\ell}(d_s-w_s+2).
$$

Thus, reducing $b$ lowers the maximum PSD-block dimension but usually increases
the block count. Total SDP size and solve time depend on the complete block and
equality structure. The coefficient-identity count stays fixed because the
assembled polynomial must still match the full target tensor.

For example, a scalar two-parameter target with $\vect M=(4,4)$ at order $\vect r=(2,2)$ has three Putinar specifications. At $b=1$, the specifications contribute $9+6+6=21$ scalar PSD windows and 25 identities. At $b=2$, they contribute $4+2+2=8$ PSD windows of dimension four and the same 25 identities. At $b=3$, every basis saturates and the request normalizes to dense Putinar, whose Gram dimensions are $9$, $6$, and $6$.

For the anisotropic target degree $\vect M=(2,6)$ at order $\vect r=(1,3)$ and $b=2$, the window block dimensions are

$$
4,4,4,2,2,2,4,4.
$$

The two axes may have different degrees and different numbers of window starts.

## Endpoint Interpretation

In one parameter, `CliqueSize=1` normalizes to Direct after order validation. In two or more parameters, size one remains SparsePutinar because the singleton Putinar generator family still differs from a direct coefficient test. If $b>1$ and $b\ge\max_{s=1}^{\ell}(r_s+1)$, every active window covers its full Gram basis and the state normalizes to dense Putinar.

## Further Reading

This tensor-window construction is distinct from the graph-chordal method of
[Zheng and Fantuzzi](https://arxiv.org/abs/2007.11410). Their method starts
from a polynomial-matrix sparsity graph. SparsePutinar instead uses
user-selected sliding windows over Bernstein Gram-basis labels. Graph-derived
cliques and chordal completion belong to the distinct structural-matrix method.

## Limitations

SparsePutinar is a fixed-order sufficient certificate. A failure may reflect
the selected order, `CliqueSize` value, grid, or numerical conditioning, so it
remains inconclusive about the continuous inequality. The caller selects the
order, strict margin, and solver. Sparse blocks trade maximum dimension against
block count, which makes solve time problem dependent.
