Both methods use the sign-normalized positive target

$$
\begin{aligned}
S^{(\mathbf c)}(\boldsymbol\alpha)
&=-\mathcal F^{(\mathbf c)}(\boldsymbol\alpha),\\
S^{(\mathbf c)}(\boldsymbol\alpha)
&=\sum_{\mathbf i}C^{(\mathbf c)}[\mathbf i]
B_{\mathbf i}^{M}(\boldsymbol\alpha),\\
C^{(\mathbf c)}&=-\mathcal C^{(\mathbf c)}.
\end{aligned}
$$

The stored rate rows have already been stacked, so the certificate notation
does not carry a rate-vertex index.

## Direct

Direct enforces

$$
\begin{aligned}
C^{(\mathbf c)}[\mathbf i]&\succeq0,\\
&\text{for every cell and label}.
\end{aligned}
$$

Nonnegative Bernstein basis functions sum to one, so this condition implies
$S^{(\mathbf c)}(\boldsymbol\alpha)\succeq0$ on the unit cell. It is the
default `pdlmi` state.
The theoretical target is strict,
$S^{(\mathbf c)}(\boldsymbol\alpha)\succ0$; the software constraints are
non-strict and require an explicit
$S^{(\mathbf c)}-\varepsilon I\succeq0$ margin when strictness is needed.

```matlab
L = residual <= 0;
constraints = L.toYalmip();
```

No Gram matrices, margin, or solver call are added.

## Pólya Elevation

For increment $d\in\mathbb N_0$, multiply the representation by the identity

$$
\prod_{s=1}^{\ell}
[\alpha_s+(1-\alpha_s)]^{d_s}=1.
$$

This produces exact degree elevation from $\mathbf M$ to
$\mathbf M+\mathbf d$. Pólya then applies
the same coefficient test to the elevated matrices
$\tilde C^{(\mathbf c)}[\mathbf i]$.

```matlab
selected = L.applyPolya(d);
constraints = selected.toYalmip();
```

The residual polynomial is unchanged. Reapplying a selector rebuilds from the
stored original residual $\mathcal F$; certificate choices do not compound.

## When To Use Each

Start with Direct. If a coarse representation has an unfavorable coefficient
even though the target appears positive, try a modest direction-wise
$\mathbf d$, refine a sensitive grid axis, or enlarge decision degree
$\mathbf m$. These are separate operations and
should be recorded separately.

## Failure Interpretation

Failure at one coefficient degree or Pólya increment is inconclusive for the
continuous inequality. Likewise, `diagnostics.problem ~= 0` supplies no valid
objective and does not prove infeasibility.

## Limitations

Both methods remain sufficient coefficient tests. Pólya can increase the number
of coefficient constraints quickly with dimension, and the package does not
search increments adaptively. Equality assembly is direct-only.

## Further Reading

- Farouki, [The Bernstein polynomial basis: A centennial retrospective](https://doi.org/10.1016/j.cagd.2012.03.001), for exact degree elevation.
