Two distinct reductions occur in the workflow. Affinity in
$\vect\nu$ makes rate-box vertex reduction exact. Bernstein, Pólya, or
Gram conditions over $\vect\rho$ are finite sufficient certificates.

## Exact Rate-Box Vertex Reduction

For fixed $\vect\rho$, write the residual as

$$
\mathcal F(\vect\rho,\vect\nu)
=\mathcal F_0(\vect\rho)
+\sum_{s=1}^{\ell}\nu_s\mathcal F_s(\vect\rho).
$$

Because $\mathcal R$ is a box and the residual is affine in
$\vect\nu$, requiring the matrix inequality at every vertex of
$\mathcal R$ is equivalent to requiring it throughout $\mathcal R$. The
runtime stores one row per distinct vertex, ordered by lower/upper
Cartesian-product choices with the last axis varying fastest. An axis whose
bounds are equal contributes one value. Therefore, the row count is $2^\ell$
only when all axes vary. For example, `[3 3]` gives one row and
`[1 1; -3 5]` gives two.

The rate-vertex index is useful while explaining or inspecting these stored
rows. After rows are stacked into the finite residual array, certificate
formulas suppress it.

## Cellwise Derivatives

Within physical cell $\mathcal H_{\vect c}$, let
$\vect\rho=\phi_{\vect c}(\vect\alpha)$ and
$P^{(\vect c)}=P\circ\phi_{\vect c}$. Then

$$
\frac{\partial P}{\partial\rho_s}
(\phi_{\vect c}(\vect\alpha))
=\frac{1}{h_s^{\vect c}}
\frac{\partial P^{(\vect c)}}{\partial\alpha_s}
(\vect\alpha).
$$

`rhodiff(P, rateBounds)` differentiates cell-local Bernstein data, aligns the
partial derivatives to a common tensor degree, multiplies them by each rate
vertex, and stores the resulting rows. See
[`rhodiff`](/GriD-LMIA/documents/reference/pdvar/rhodiff/) for its input
and output contract.

## Shared Values, Different One-Sided Slopes

A continuous piecewise-polynomial `pdvar` shares full face-control handles
between neighboring cells. Therefore its values agree on each face. The
normal derivatives may differ:

$$
\begin{aligned}
P_{\vect c^-}|_{\text{face}}
&=P_{\vect c^+}|_{\text{face}},\\
\nabla P_{\vect c^-}|_{\text{face}}
&\ne\nabla P_{\vect c^+}|_{\text{face}}
\quad\text{is allowed}.
\end{aligned}
$$

This is $C^0$ piecewise-polynomial storage with cellwise derivatives that may
differ across faces.

## Clarke Interface Coverage

A continuous piecewise-polynomial matrix function on compact
$\mathcal P$ is locally Lipschitz. At a shared face, its Clarke generalized
derivative lies in the convex hull of the limiting cell-side derivatives.
Because the DPD-LMI is affine in those derivatives, imposing the inequality
for every adjacent cell-side limit covers that convex hull.

This argument closes the interface gap through value continuity and one-sided
cell derivatives. It applies to the continuous decision $P$. Discontinuous
coefficient-backed `pdmat` data follow their stored one-sided values.

## Exact Versus Sufficient

| Step | Logical status | What remains |
| :--- | :--- | :--- |
| Rate-box vertices | Exact for affine $\vect\nu$-dependence | Continuous $\vect\rho$-domain |
| Cell-side interface checks | Covers Clarke convex hull under continuity and affinity | Positivity on each cell |
| Direct, Pólya, or Gram certificate | Finite sufficient condition | Possible conservatism at fixed settings |

Exact rate reduction remains valid after a failed certificate. The certificate
failure remains inconclusive about the original continuous inequality.

## Limitations

The exact vertex statement requires affine dependence on
$\vect\nu$ over a hyperrectangle. The interface argument requires
value continuity and local Lipschitz regularity of the decision function.
Discontinuous known data must be analyzed cellwise, and nonlinear rate
dependence would need a different treatment.
