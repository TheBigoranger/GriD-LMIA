The physical grid and the local Bernstein degree are independent modeling
choices.

## The Two Independent Choices

For scheduling axis $s$, define the ordered grid

$$
\mathcal G_s=\{\rho_s^{(1)},\ldots,\rho_s^{(k_s)}\}.
$$

The one-based symbol $\rho_s^{(j)}$ denotes physical node $j$ on axis
$s$, while $k_s$ is that axis's node count.

The one-based physical cell index
$\mathbf c=(c_1,\ldots,c_\ell)$ selects

$$
\mathcal H_{\mathbf c}
=\prod_{s=1}^{\ell}
[\rho_s^{(c_s)},\rho_s^{(c_s+1)}],
\qquad
h_s^{(\mathbf c)}
=\rho_s^{(c_s+1)}-\rho_s^{(c_s)}.
$$

The grid determines where cells begin and end. The decision degree $m$
determines how many Bernstein labels live inside each cell. Refining
$\mathcal G_s$ does not raise $m$, and raising $m$ does not add physical
cells.

## One-Dimensional Input

For $\mathcal G_1=\{0,0.5,1\}$, there are two cells. The forward pullback
from a physical point $\boldsymbol\rho\in\mathcal H_{\mathbf c}$ to the unit
cell is

$$
\boldsymbol\alpha=\phi_{\mathbf c}(\boldsymbol\rho),
\qquad
\alpha_s=
\frac{\rho_s-\rho_s^{(c_s)}}{h_s^{(\mathbf c)}}\in[0,1].
$$

“Forward” matters: $\phi_{\mathbf c}$ maps physical coordinates to local
coordinates. The inverse map is
$\rho_s=\rho_s^{(c_s)}+h_s^{(\mathbf c)}\alpha_s$.
Consequently,

$$
\frac{\partial}{\partial\rho_s}
=\frac{1}{h_s^{(\mathbf c)}}
\frac{\partial}{\partial\alpha_s}.
$$

For degree $m=2$, each cell has labels $i=0,1,2$, but a continuous
`pdvar` shares the endpoint handle across the interface.

## Two-Dimensional Input

An anisotropic grid is valid and often useful:

```matlab
grid = {[0 0.25 1], [-1 1]};
A = pdmat(grid, @(rho1,rho2) [1+rho1 rho1*rho2; rho1*rho2 2+rho2^2], ...
    Degree=2);
```

The first axis has two physical intervals and the second has one. Every cell
still uses local coordinates
$\boldsymbol\alpha=(\alpha_1,\alpha_2)\in[0,1]^2$.
For tensor degree $m=2$, each local coefficient array has
$(m+1)^2=9$ labels $\mathbf i=(i_1,i_2)$.

## The ell-Dimensional Case

The number of physical cells is
$\prod_{s=1}^{\ell}(k_s-1)$. For scalar tensor degree $m$, each cell has
$(m+1)^\ell$ local labels. The two products measure different things:
physical partition size and local polynomial representation size.

`pdbase.cells()` traverses physical cells, while `pdbase.labels()` traverses
zero-based Bernstein labels. `LocalValues` stores the corresponding nested
cell structure. See [pdbase storage and inspection](/PD-LMI-package/documents/reference/pdbase/storage-inspection/)
for the exact traversal contract.

## Do Not Conflate These Operations

- Grid refinement changes the physical partition and may localize
  conservatism.
- Degree elevation changes only the Bernstein representation of the same
  polynomial.
- Increasing decision degree $m$ enlarges the decision-function family.
- Increasing residual degree $M$ can result from products and common-degree
  alignment even when $m$ is unchanged.
- Increasing Pólya increment $d$, Gram order $r$, or SparseFullBox
  bandwidth $b$ changes the selected finite certificate.

## Limitations

The implemented geometry is a tensor-product box grid. Grid knots must be
ordered, cell widths must be positive, and the package does not infer adaptive
or simplex partitions. Discontinuous coefficient-backed `pdmat` data are
supported, but the shared-face continuity argument for decisions does not
extend to such known data automatically.
