`pdlmi` exposes exactly five certificate states: **Direct**, **Pólya**,
**Putinar**, **SparseFullBox**, and **FullBox**. One-parameter
Markov–Lukács is the interval form used by Putinar and FullBox, not a sixth
software state.

## Certificate Map

<CertificateFlow />

All five paths start from the same original residual $\mathcal F$. The
comparison relation determines the sign-normalized positive target $S$.
Alternative selectors rebuild from $\mathcal F$; they do not compound.

<CertificateChooser />

Exact rate-box vertex reduction occurs before this map. Each certificate is a
finite sufficient condition over the remaining parameter cell. These are
different logical steps.

## A Tiny Example: Positive Polynomial, Failed Direct Test

A polynomial may be positive on $[0,1]$ even when one Bernstein coefficient
is negative. Failure of Direct therefore does not prove negativity. Pólya or a
Gram certificate may certify the same target without changing the underlying
continuous inequality.

## Full-Space SOS

Full-space SOS is useful background but is not a selectable `pdlmi` state.
The implemented Gram paths use interval or box generators and exact Bernstein
coefficient matching on $[0,1]^\ell$.

## Direct Bernstein Coefficient Certificate

Direct requires

$$
C^{(\mathbf c)}[\mathbf i]\succeq0
$$

for every physical cell, stored rate row, and local label. It is the default,
has no Gram variables, and inserts no hidden positivity margin.

## <span id="polya-type-coefficient-relaxation"></span>Pólya-Type Coefficient Relaxation

Pólya applies exact degree elevation by increment $d$, then runs the Direct
test on the elevated coefficients. Read
[Direct And Pólya](/PD-LMI-package/documents/math/finite-certificates/direct-and-polya/)
for the formula and selection boundary.

## Putinar Quadratic Modules

For one parameter, the minimum absolute order is
$r=\lfloor M/2\rfloor$. For two or more parameters
$(\ell\ge2)$, Putinar uses an unweighted Gram/SOS term plus the singleton
generators $g_s=\alpha_s(1-\alpha_s)$, with minimum
$r=\lceil M/2\rceil$.

### Implemented Putinar selector

```matlab
selected = L.applyPutinar();   % default absolute order
selected = L.applyPutinar(r);  % explicit absolute order
```

In one parameter this selector uses the exact parity-specific
Markov–Lukács interval form. See
[Markov–Lukács And Putinar](/PD-LMI-package/documents/math/finite-certificates/markov-lukacs-and-putinar/).

## Schmüdgen And Full Preorderings

The full-box preordering uses every square-free product
$g_J=\prod_{s\in J}\alpha_s(1-\alpha_s)$. The software state is
`FullBox`.

<span id="sparse-full-box-tensor-windows"></span>

## SparseFullBox Band-Limited Certificate

The mathematical construction is FullBox with **band-limited Gram support**.
The software state is `SparseFullBox`, selected with bandwidth
$b$. Width one canonicalizes to Direct after order validation; width at least
$r+1$ canonicalizes to FullBox.

### Worked full-box example: two parameters, degree three

<span id="worked-full-box-example-two-parameters-degree-three"></span>

For a two-parameter target with assembled degree $M=3$, FullBox introduces
Gram terms for the empty subset, both singleton generator subsets, and their
two-axis product. Each term is mapped into the Bernstein basis and the sum is
matched exactly to every $C^{(\mathbf c)}[\mathbf i]$. SparseFullBox retains
those term families and exact identities but restricts dense Gram support to a
band-limited form. The implementation decomposes that support into overlapping
axis-aligned tensor-window PSD cliques.
The detailed basis-order boundary is documented in
[SparseFullBox And FullBox](/PD-LMI-package/documents/math/finite-certificates/sparsefullbox-and-fullbox/).

## One-Dimensional Markov–Lukács Forms

Even and odd assembled degrees use different endpoint weights. The package
implements those parity forms through Putinar, SparseFullBox, and FullBox
selectors in one parameter.

## Four Operations That Are Not Interchangeable

- Refine $\mathcal G_s$ to change physical cells.
- Raise decision degree $m$ to enlarge the decision family.
- Raise Pólya increment $d$ to elevate the representation.
- Raise absolute Gram order $r$ or SparseFullBox bandwidth $b$ to change
  a Gram certificate.

Assembled residual degree $M$ is determined after algebra and alignment; it
is not another user-selected certificate knob.

## Exact Software Boundary

The package implements five finite states only. It does not implement a
general-domain Putinar parser, an adaptive sparse-pattern search, or a
solver-owned hierarchy loop. A failed fixed $d$, $r$, or $b$, a nonzero
`diagnostics.problem`, or an aborted solve is inconclusive for the original
continuous feasibility question.

## Limitations

Every certificate is sufficient over a tensor-product cell. Gram blocks can
grow quickly with dimension and order. Equality assembly is direct-only, and
no certificate adds a strict margin automatically.
