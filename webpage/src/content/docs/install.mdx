## Requirements

- MATLAB.
- YALMIP already on the current MATLAB path. The installer requires its `yalmip`,
  `sdpvar`, `sdpsettings`, `optimize`, and `getavailablesolvers` entry points.
  The caller installs YALMIP and exposes it on the MATLAB path.
- A working SDP solver exposed by YALMIP. The installer probes MOSEK, COPT,
  SeDuMi, SDPT3, then LMILAB, accepting the first candidate that solves a
  small bounded SDP successfully.

## Release-Pinned Clone And Code Ocean Preparation

Clone the immutable release from a terminal, then open MATLAB in that checkout:

```sh
git clone --depth 1 --single-branch --branch v1.5.1 https://github.com/TheBigoranger/GriD-LMIA.git
cd GriD-LMIA
```

This relative workflow is also suitable for preparing a future Code Ocean
Capsule. The clone supplies the package and examples. The Capsule environment
must separately provide MATLAB, YALMIP, and an available SDP solver. Four of the
five public scripts default to SDPT3. `discrete_time_robust_stability.m` defaults
to SeDuMi. Script solver defaults remain separate from installer solver discovery.
Code Ocean execution and Markdown rendering remain unverified.

## One-Call Setup

```matlab
report = install_pd_lmi();
```

Run the command from the package root. It adds only that repository root at
the end of the MATLAB path. It adds the repository root directly and keeps
`doc`, `webpage`, test, metadata, and generated directories as ordinary
subdirectories. Exact-path idempotence means a second call keeps one root
entry. The installer checks for class shadowing before saving the
MATLAB path, so a failure restores the previous path instead of leaving a
partial installation.

`report` contains `PackageRoot`, `YALMIPRoot`, the working `Solver`, the
`AddedPaths`, and whether the path was `Persisted`. Calling `install_pd_lmi()`
with an omitted output performs the same idempotent installation.

## Failure Behavior

The installer stops with a stable error identifier for an unsupported
configuration. Typical failures are `install_pd_lmi:MissingYALMIP`,
`install_pd_lmi:IncompleteYALMIP`, `install_pd_lmi:NoWorkingSDPSolver`,
`install_pd_lmi:PathConflict`, and `install_pd_lmi:PathSaveFailed`. Resolve
the reported dependency, solver, or path conflict and run the one command
again. The installer owns the package-path setup and persistence step.

If the environment permits session paths but saving `pathdef.m` fails, use this
fallback **only** for `install_pd_lmi:PathSaveFailed`. Run it from the clone root.
All other installer failures remain errors:

```matlab
packageRoot = pwd;
try
    report = install_pd_lmi();
catch exception
    if strcmp(exception.identifier, 'install_pd_lmi:PathSaveFailed')
        addpath(packageRoot, '-end');
        warning('GriD-LMIA is available for this MATLAB session only.');
    else
        rethrow(exception)
    end
end
```

The installer restores the previous path when persistence fails. The fallback
re-adds only the repository root for this session and must be repeated in each
new session. A successful installation report and persistent setup require
the installer to complete successfully. This fallback provides session access only.

## Verify

```matlab
results = tests.run_all();
```

The release gate is `tests.run_coverage()` with zero failed and zero incomplete
results while meeting the production coverage baselines. The accepted v1.5.1
full-suite and coverage runs each passed 886/886 runtime tests, including the
171-entry API gate. Production coverage is 3751/3874 statements (96.82%) and
1929/2042 decisions (94.47%). The README example and all five public scripts
passed their documented acceptance checks, including the expected absence of
a common quadratic certificate for the second mass-spring-damper box.

See the [current release evidence](/GriD-LMIA/version-history/#v1-5-1).
Historical counts belong to their own version entries. Accepted solver smoke
cases require `problem == 0`.
